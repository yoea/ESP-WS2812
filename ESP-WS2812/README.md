## 硬件与链路

| 项 | 值 |
|---|---|
| 板卡 | **WeMOS D1 mini**，4MB flash（esptool 实测自动识别） |
| 烧录 | USB 转串口（CH340），DTR/RTS 自动进下载；端口**自动探测**（当前 COM3） |
| 信号线 | **GPIO4 = 丝印 D2**（`GPIO0` 是 strapping 脚，上电被拉低会进下载模式，不用它） |
| 板载 LED | **GPIO2 = 丝印 D4**，低电平点亮，可正常控制 |
| 物理灯珠 | 60 颗 WS2812B |
| 波特率 | 115200 |
| 供电 | **必须外接 5V ≥3A 并与板子共地**；60 颗全白理论 3.6A，USB 口带不动 |

电脑端发 **60 组 RGB（180B）**，每颗灯珠单独一个颜色 —— v6 固件逐颗
`setPixelColor(i, ...)`，不再做「每组复制 2 颗」。帧长 185B @50Hz
= 92.5 kbit/s，占 115200 的 **80.3%**（100Hz 会超带宽，所以锁 50Hz）。

## 固件协议（v6，二进制帧）

帧格式 `A5 5A | CMD | LEN | PAYLOAD[LEN] | CRC8`；CRC8 覆盖 CMD+LEN+PAYLOAD，
多项式 0x07、初值 0x00。

| CMD | 名称 | payload | 说明 |
|---|---|---|---|
| 0x01 | SET_ALL | 180B | 60 颗逐颗，第 i 颗 = `payload[i*3..i*3+2]` |
| 0x03 | BRIGHTNESS | 1B | 0-255，**固件 clamp 到 128（50% 硬限）**；会先 `clear()` 再 `show()`，绝不点亮旧数据 |
| 0x04 | HEARTBEAT | 0B | 3 秒无帧则渐灭 / 板载灯呼吸失联提示 |
| 0x06 | OFF | 0B | 清灯珠数据 + 亮度归零 + 板载灯灭，停心跳也不报警 |
| 0x07 | STATUS_LED | 1B | 板载灯 0=灭 1=常亮 2=慢闪 |
| 0x08 | STATUS_PULSE | 1B | 板载灯短闪几下（事件提示） |
| 0x10 | HANDSHAKE | 0B | 回应 **17B 身份帧**：`[0]`=版本 **6**、`[1..12]`="D1MINI-LED60"、`[13..16]`=芯片 ID（小端）。host 逐个串口探测，只认身份匹配的设备 |

`MAX_PAYLOAD=192`；单帧串口 16.1ms + 60 颗 `show()` 1.8ms ≈ 17.9ms，
20ms 帧间隔余量约 2ms；关中断期间最多落 ~21 字节到 UART FIFO（128B），不丢帧。

### 串口自动识别（固件身份证 + 序列号绑定）

**不写死 COM 号，也不靠「谁先枚举到」。** v6 固件在握手回应里带 17B 身份帧：
`[0]` 固件版本 6、`[1..12]` 型号 `D1MINI-LED60`（D1 mini）/ `ESP01S-LED60`（ESP-01S）、`[13..16]` `ESP.getChipId()`
（每片 ESP8266 出厂唯一，烧录时无需手填序列号）。

**三层判定，逐层收紧：**

1. **端口** —— `candidate_ports()` 列出候选（指定端口优先 → CH340/USB-SERIAL → 其余）。
2. **型号 + 版本** —— 逐个打开、发 `CMD_HANDSHAKE`、按 LEN 收完整帧，`parse_identity()`
   校验；不匹配就关掉换下一个口，绝不往别人设备写数据。
3. **序列号（`host/device.json`）** —— 型号能撞（固件都一样），芯片 ID 是烧死的。
   第一次连上时记下这一个序列号，之后只认它：

| 情况 | 行为 |
| --- | --- |
| 只有一台候选 | 自动记住，无感知 |
| 多台候选 · 前台终端 | 列出端口 / 型号 / 序列号，问你要控制哪一台（回车默认第 1 台，`q` 放弃） |
| 多台候选 · 后台自启（无 stdin） | 不提问（问了会卡死），暂用第一台且**不写绑定**，日志提示 `--select-device` |
| 绑定那台换了 USB 口 | 按序列号重新定位，新端口自动写回 `device.json` |
| 插着的是另一块同型号板 | **拒绝接管**，明确报「绑定的设备（序列号 X）不在场」 |
| 绑定那台没插 | 同上，每 3s 重试，插回即接上 |

`device.json` 长这样（端口只是缓存，不用手改）：

```json
{
  "serial": "00A30BD0",
  "port": "COM3",
  "model": "D1MINI-LED60",
  "version": 6,
  "bound_at": "2026年11月9日 20:30:00",
  "updated_at": "2026年11月9日 20:30:00"
}
```

三条命令管这件事：

```powershell
python led_host_60.py --list-devices      # 扫描：每个口是什么、哪台是绑定的
python led_host_60.py --select-device     # 换一台（也可 --select-device COM3 只探那个口）
python led_host_60.py --forget-device     # 忘掉绑定，下次启动重新询问
```

`--port COM3` 仍然可用，语义是**临时首选**：只在本次运行生效，不写 `device.json`，
身份不符照样扫其余串口。

- Web 详情框显示实际端口 + `型号 / 固件版本 / 序列号`，另有一行「设备绑定」；
  顶部胶囊显示端口名（如 `COM3 正常`）。
- `reconnect()` 同样遍历 + 校验，并且**比对序列号**：插的要是别的板子，宁可不连。
- **向后兼容 v5**：没烧 v6 的板子只回 1B 版本号，`parse_identity()` 也接受（标 `legacy`），
  灯效照常；但它没有身份证、**不能绑定**，多台在线时无法区分 —— 烧 v6 才有这层保障。

**烧录 v6（第一次需要把板子插上）**：
```powershell
powershell -ExecutionPolicy Bypass -File "D:\Develope\esp8266\3.WeMOS D1 mini\ESP-WS2812\flash_d1mini.ps1" -Port COM3
```
`-Port` 换成设备管理器里**当前在线**的 COM 号即可；脚本会优先挑 `Status=OK` 的 CH340，
并停服务→编译→烧录→恢复服务。烧完后重启一次服务，Web 详情框就能看到
`D1MINI-LED60 · v6 · 序列号 XXXXXXXX`。烧录期间若板子没插，脚本会明确报
「没检测到 CH340 串口」，不会误烧别的设备。


关键参数：不指定端口（按 `device.json` 的序列号认灯带）、`LED_COUNT=60`（**逐颗独立控色**）、
`FRAME_HZ=50`（185B 帧的带宽上限）、
`--render-attack 0.010` / `--render-release 0.090`（**放歌 + 麦克风 VU 共用**的快起慢落 1:9；参数名沿用历史）。
亮度由 v6 固件 50% 硬限，host 的 `--brightness` 仍发 255，别再拿 `--max-level` 二次打折。
**换 USB 口不用改任何参数**：脚本按序列号重新定位，新端口自动写回 `device.json`。

终端面板**不再逐帧打印 60 颗灯珠的实时色块**（又占地方又看不清），
只保留「输出 x/60 颗 · 亮度 · 峰值」一行数字；`--diagnose` 的静态预览每 4 颗抽样 1 个。

## 麦克风电平表：60 段连续彩虹（最高优先级）

**麦克风被占用时（不管有没有在放歌）**，音量同时决定亮几颗 / 什么颜色 / 多亮。
它是「状态提示」而非氛围灯，优先级压过封面配色与环境彩虹：直播、K 歌、
游戏语音同时放背景音乐时也让电平表顶上来，并直接绕过音乐停后的 1.5s 缓冲。

> ⚠️ 代价：`MicWatcher` 读的是 ConsentStore 注册表占用记录（0.2s 开 / 1.5s 关去抖），
> **常驻占麦的 App 会让封面灯效长期不出现** —— Discord、腾讯会议、挂着麦克风权限的
> 浏览器、语音输入法都在内。放歌却不显示封面时，先跑 `python led_host_60.py --diagnose`
> 看是谁占着麦克风。要缓解得加麦克风进程白名单，目前没做。

- **颗数**：真静音（`lv < 0.02`）全灭；门限刚过的**底噪级别约 1 颗**，
  `lv=1.0` 才亮满 **60 颗**。曲线是 `n = 1 + t^1.5 × 59`，**低段刻意压慢**，
  见下面「低电平不再突然亮一片」。
- **颜色**：沿亮起顺序 `mic_hue(i)` 从 **绿 120° 线性走到红 0°**，
  60 颗就是 60 段、相邻差约 2°，中途自然经过黄 60° / 橙 30°。
  **不是**「前几颗绿、再几颗黄」那种四五段硬分段。
- **亮度**：最终 PWM 占空比直出（不过 gamma），底噪 1.2% → 满档 80%，单调递增；
  前 10% 电平从 1.2% 连续爬到 5%（约 3 → 13/255），不再是旧版那条几乎水平的
  平段。起点不为 0，否则门限刚过那颗会被 `int` 截断成 0/255 而物理全黑。
- **响应**：电平低通与放歌共用 `--render-attack 0.010` / `--render-release 0.090`
  （快起慢落 1:9），详见下面「瞬时峰值打得到」。
- **严格 60 级档位**：`vu_steps(n)` 把 `mic_led_count()` / `render_led_count()`
  算出的 `n` 拆成「whole 颗满亮 + 下一颗按小数渐入」。
  **没有 `frac>0.06` 迟滞，也没有「最后一颗单独延后」** ——
  那两条是 8 颗时代怕「到顶太早」的补丁，在 60 级分辨率上只会吞精度、
  让第 60 颗几乎不出现。现在 `lv=1.0` 恰好 60 颗全亮，面板显示的小数
  就是最后一颗的渐入比例，数字与肉眼一致。

### 低电平不再突然亮一片：颗数与亮度曲线配套

现象：声音极小时一个灯都看不见，到某电平突然亮四五颗。根因不是单纯「亮度太低」，
是 **60 颗下两条曲线脱节**：8 颗时代 `1+lv×7`，`lv=0.1` 才 1.7 颗；换 60 颗后
`1+lv×59`，`lv=0.1` 已经 6.9 颗，而亮度曲线前 10% 仍是几乎水平的 2/255。
于是 `lv=0.02~0.10` 颗数从 1 铺到 6 却全黑，到 `lv≈0.13` 亮度越过可见阈值时
**8 颗一起显形**（放歌是 `lv=0.06` / 5 颗）。

现在两条一起改：
- 颗数 `VU_COUNT_EXP = 1.5`：低段慢、高段快，`lv=0.10` 只 2.4 颗，`lv=1.0` 仍 60 颗；
- 麦克风亮度 `MIC_BRIGHT_STOPS` 前端抬起来（1.2% → 5% @`lv=0.10` → 80% @1.0）；
- 放歌亮度 `RENDER_BRIGHT_GAMMA = 0.7`（`lv^0.7`，满档 `RENDER_BRIGHT_MAX=1.0`，
  host 不再二次打折，上限交给固件 128 硬限）。

实测可见分界（以 ≥8/255 算）：麦克风从 `lv=0.13 / 8 颗` 提前到
**`lv=0.061 / 1.5 颗`**，放歌从 `lv=0.06 / 5 颗` 提前到 **`lv=0.018 / 1.1 颗`**
—— 每颗亮起时立刻看得见，于是一颗一颗长出来。
代价：中段比原来略亮、橙红段更难满，第 60 颗也从 `lv≈0.983` 推到
**`lv≈0.99`** 才出现（满档更珍贵）；嫌亮把 `RENDER_BRIGHT_GAMMA` 调大
（1.0 回到线性），想让高段更容易满把 `VU_COUNT_EXP` 调小（1.0 回到线性）。

### 瞬时峰值打得到：快起慢落 10/90ms + 颜色平滑 12ms

8 颗时代的两级 35ms 低通串联会把鼓点削平：实测 `lv=0.9` 只持续 1~3 帧时，
理想 **54 颗**只打到 **31~47 颗**（放歌 39~52 颗），等于 60 级分辨率被砍掉一大截。
现在颜色平滑 `MIC_SMOOTH_TAU` 是 **12ms**（50Hz 下一帧跟上 81%）；
电平低通统一为 `--render-attack 0.010` / `--render-release 0.090`（快起慢落 1:9），
**放歌与麦克风 VU 共用这一对参数**（`Monitor` 里两个 `MicLevel` 都传它）。
参数名沿用历史 `--render-*`，别被 "render" 误导。

上升只由 attack 决定：慢落 25/90ms 下短促峰值逐帧完全相同
（48.5 / 53.3 / 54.0 / 54.1 颗）；90ms 的慢落把谷值托住（方波 0.1 -> 0.187），
整条更稳、不那么闪。代价是拖尾：峰值后落到 `lv<=0.3` 从 60ms 变 180ms
（麦克风从 40ms 变 180ms），说话/鼓点停了灯会 linger 一会儿。

⚠️ `--autostart install` 会把这两个参数写死在任务命令行里，改默认值对已装
任务无效：要吃到新值需重跑一次 install（或在任务计划里手动改参数）。
颜色平滑是常量，**重启服务即生效**，不受此限制。

### 低亮度闪烁：亮度系数单独慢平滑

现象：暗封面的前 12 颗、以及亮/灭交界的渐入颗会闪。根因是**低亮度整数量化**：
低电平时 `scale(gamma_base, bright)` 用 `int` 截断，暗色灯珠的 `raw` 全是
`(0,0,0)`，发光完全靠 `with_glow()` 的整数 `floor`；而 `floor` 跟着瞬态亮度
每帧在 1/2/3/4 之间跳 —— `1↔2` 就是亮度翻倍，补底颜色按感知域比例取整也
跟着跳（`(3,3,4)` ↔ `(3,3,3)`），亮度和色相同时闪。渐入颗更明显：`fade`
是 `n` 的小数部分，会随电平每帧在 0.33↔0.58 大幅跳，`floor` 于是在 1↔3
之间跳（三倍亮度）。

**已做的缓解**：`RENDER_BRIGHT_TAU = 0.12`，把**亮度系数**（`bright` /
`glow_level`）单独做 120ms 低通，颗数仍用原始电平。实测 `floor` 随亮度的随机
台阶从 119 次/120 帧降到 5 次，面板亮度改显示实际发出的平滑值。
**但这只解决了一半**：前 12 颗输出跳变在 `lv=0.25` 仍是 3/255，因为主因是
下面这条渐入颗抖动。`Monitor._bright_value` 是唯一新增的运行状态。

**真正的残余 / 待定**：渐入颗的 `fade` 是 `n` 的小数部分，随电平每帧在
0.33↔0.58 大幅跳；渐入颗的位置也随快起电平跳动，那颗灯会在「满亮 / 渐入」
之间切换。只要颗数保持 10ms 快起，就消不掉这 2~3/255 的跳变。
模拟过平滑 fade / 压缩渐入幅度 / floor 不乘 fade / 连续混合 / 滞回淡入，
要么无效要么更差。给颗数整体加 60ms 低通能把跳变压到 **1/255**，
但短促鼓点的快起从 51.4 颗降到 14.6 / 25.0 / 32.5 颗（1/2/3 帧），明显迟钝。
这是「不闪 vs 跟手」的取舍，等用户拍板，暂未改。

## 无 SMTC 曲目时的环境彩虹（打游戏 / 系统音效）

拿不到 SMTC 音乐信息时（例如打游戏），`render_meter` 一直在读输出峰值，
只是旧版没被灯效用上；现在多了 `ambient` 态。状态优先级按下面从上到下：

| 条件 | 状态 | 表现 |
|---|---|---|
| 麦克风被占用（**不管有没有在放歌**） | `mic` | 60 段绿→红电平表（**最高优先级**） |
| 有 SMTC 音乐、麦克风没占用 | `media` | 封面配色 + 输出峰值 |
| 无 SMTC、麦克风没占用、输出端点有声音 | **`ambient`** | **环境彩虹**：电平决定亮几颗，默认全灭 |
| 完全静音 / 输出端点不可用 | `mic` / `idle` | 全灭、板载也灭 |

**默认全灭**，有输出声音才按电平逐颗长出一条彩虹 —— 手感与放歌完全一致：
本质上就是把放歌那帧的「封面色」换成固定彩虹色。

- **颜色**：60 颗固定 300° 色相渐变（红→紫，首尾不撞色），按物理位置铺，
  静止不流动、不呼吸。基色是 `v=1.0` 的 PWM 域纯 HSV，`raw` 直出**不过 gamma**，
  也不需要 `with_glow` 补暗灯（没有深色灯珠）。
- **颗数**：`render_led_count(lv) = 1 + lv^1.5 × 59`，与放歌同一条曲线；
  `vu_steps()` 严格 60 级、下一颗按小数渐入。静音 0 颗、极小声 1 颗、
  `lv=1.0` 才亮满 60 颗。
- **电平动态**：同一个 `render_level`（快起 10ms / 慢落 90ms），
  `tick()` 的颜色平滑也按声音驱动态走 12ms（150ms 会明显比放歌迟钝）。
- **亮度**：同一条 `render_brightness()` 曲线（1% → **100%**，`lv^0.7`）+
  同一个 120ms 低通 `_bright_value`（放歌 / 彩虹共用，切态不跳）。
  `AMBIENT_BRIGHT_GAIN` 已从 2.0 归到 **1.0**：放歌上限放开后再乘 2 会
  全程被 clamp 到满亮、把曲线形状压平，所以两条灯效现在逐帧同一口径，
  满档都由固件 128 硬限。
- **静音判定**：慢落之后的 `render_level.value < RENDER_SILENCE_GATE` 才全灭
  （放歌用的是瞬时 `peak`），游戏音效断续时不会硬切成全黑；
  状态本身也不随「有没有声音」切换，避免状态切换脉冲狂闪。
  另加 `AMBIENT_ON_DELAY = 0.4s` 起灯去抖：静音→有声要连续 0.4s 超门限才亮，
  端点刚枚举的毛刺 / 系统零碎提示音打不亮第一颗；设成 `0` 即与放歌同瞬间起步。
- 面板显示 `环境彩虹 x.x/60 颗 · 亮度 · 峰值`，与放歌那行同一个口径。
- 代价：颗数随电平变之后，低亮度段会重新出现整数台阶（放歌也有，
  120ms 亮度低通已把它压住），不再享受旧「全亮 + 只调亮度」的零台阶特性。

## 开机 / 关机 / 休眠：fail-safe 全灭

**不去「监听开关机」**。后台跑的是 `pythonw`（无控制台），Windows 关机直接杀进程，
`finally: strip.off()` 根本执行不到，`CTRL_SHUTDOWN_EVENT` / 任务计划的事件触发器
都来不及写串口；而多数主板 USB 在 S5 仍供电，板子**不重启**，`pixels` 里
留着关机前最后一帧颜色。旧行为有三处漏洞：

| 阶段 | 旧行为 |
|---|---|
| 关机 | OFF 没发出；固件 3 秒后只把 `currentLevel` 渐灭到 0，**颜色数据没清** |
| 开机空窗 | `LogonTrigger` 延迟 20s + `--wait-port`（上限 30s，握手成功即返回），期间无人管灯带 |
| 第一条帧 | `CMD_BRIGHTNESS` 恢复亮度并 `show()`，把关机前那一帧**原样复活** → 「中间亮一颗」 |
| 登录音效 | ambient 检测到输出峰值，按电平亮起 1 颗（不是残留，但看着一样莫名） |

现在按三层堵死，原则是**灯带默认灭，不依赖主机关机那一刻发 OFF**：

- **L1 固件**：`setup()` 里 `begin()` 后先 `clear()` 再 `show()`（`malloc` 缓冲区不保证清零）；
  `CMD_BRIGHTNESS` 分支改成 `clear()` → `setBrightness()` → `show()`，
  亮度帧永远不点亮旧数据。没人推 `SET_ALL` 时灯带一定是黑的。
- **L2 host**：新增 `LedStrip.blank()`（`CMD_OFF` + 全 0 的 `SET_ALL` + 板载灭），
  `main()` 启动、`resume()` 重连，第一条指令一律是 `blank()`
  **然后**才发亮度；重连后把 `Monitor.current` 和 ambient 去抖计时一并清零，
  避免颜色平滑把断链前那一帧 lerp 回来。L2 单独也能挡住旧数据复活（数据已被全 0 覆盖），
  不烧新固件也有效。
- **L3 开机静默**：`BOOT_QUIET_SEC = 12s`，只在自启命令行
  （带 `--wait-port` / `--background`）启用，期间状态机照常跑、灯带强制全灭，
  `current` 也直接清零（否则 150ms 平滑会变成「缓缓熄灭」）。
  加上 ambient 的 0.4s 起灯去抖，登录音 / 通知音 / 端点毛刺都点不亮灯。
  前台手动运行 `python led_host_60.py` 不启用静默期，改完立刻能看效果。

没做「隐藏窗口收 `WM_ENDSESSION` / `WM_POWERBROADCAST`」那套：关机响应窗口只有几秒、
后台无窗口进程还得自己起消息泵，复杂且不可靠，只能当休眠/锁屏的补充，不能当主力。
真正想要关机必断电，可以在 BIOS 开 ErP Ready / 关 S5 USB 供电（代价是别的 USB 待机充电失效）。

## 硬件变体（历史）

本目录现在只维护 **WeMOS D1 mini** 版：数据脚 `D2`（GPIO4），板载 LED `D4`（GPIO2，低电平点亮），
型号字符串 `D1MINI-LED60`，板型 `esp8266:esp8266:d1_mini`。

早期用过 ESP-01S（数据脚 GPIO0、型号 `ESP01S-LED60`）。两者协议逐字节相同，所以
`DEVICE_MODELS` 里仍然兼容它，插回来不会被误判成陌生设备；但板子、固件和烧录脚本
都已归档到 `../ESP-01S-LightStrip-60/`，不再维护。

- 数据脚用 D2 而不是 GPIO0：后者是 strapping 引脚，上电被拉低就进下载模式，
  挂长线还容易受干扰。D1 mini 有富余 IO，没必要冒险。
- `device.json` 按芯片序列号绑定；插的是另一块板会明确报「绑定的设备不在场」，
  不会把 60 颗的帧发给别人的灯带。
- 换板子**不用改任何主机代码**，往 `DEVICE_MODELS` 追加一条型号即可。

**当前：D1 mini + v6 固件，绑定序列号 `0031B53A`。**

> （见上一节「硬件变体」），不是这里说的 8 颗那套。

**10 种装饰模式右上角都有设置点**（`auto` / `off` 没有）。点开后：

每次请求都重读文件。

`sample_frame()` 按区间平均成 14 段（保留渐变与「亮了几颗」的分布），经
`/api/frame` 暴露；面板每 150ms 拉一次并放大到可见亮度，实时反映当前灯带。
只在 `current === "auto"` 时启用，其它 11 张卡片的固定演示预览与灯珠数量都不变。
页面隐藏（`document.hidden`）时暂停轮询，省移动端流量；模式列表仍每 5 秒同步一次，
外部改了模式也能看到。

### 机制与三种语义

| 选择 | 行为 |
|---|---|
| `auto` | **原有灯效**：放歌 → 封面配色 + 输出峰值；麦克风占用 → 60 段电平表；游戏 / 无 SMTC 但输出有声 → 环境彩虹电平（默认灭，按电平亮几颗）；什么都不播放 → 全灭。开机静默期 12s 只在 `auto` 下生效 |
| `off` | **整条永远不亮**，覆盖一切状态 |
| 其余 10 种 | **强制常亮**：不管是否播放音频、是否开麦克风、是否在打游戏、是否处于开机静默期，都保持所选灯效，**绝不自动让位** |

实现上 `tick()` 的分支顺序是 `off` → 装饰 → `auto`（含静默期）。`compute_target()`
始终照常跑（状态机、面板显示的当前态、媒体与电平采样都不受影响），只是输出帧
被选中的模式整个替换；装饰切换走 12ms 颜色平滑，渐变过去不硬切。

- **模式 / 颜色 / 强度统一存一个 `host/idle_state.json`**（旧的 `idle_mode.txt` +
  `idle_colors.json` 会在首次启动时自动迁移进来，之后不再读写）：
  ```json
  {"mode": "solid",
   "colors": {"solid": {"hex": "#2EE6A8"}},
   "levels": {"solid": 0.5, "rainbow": 0.5}}
  ```
  旧格式把 `level` 内嵌在 `colors` 里，读取时会自动搬到 `levels`，不丢用户设置。
  **重启服务后保持**；主循环每 0.5s 查一次 mtime，直接用记事本编辑该文件也生效。
  写回走 `os.replace` 原子替换，poll 不会读到半截 JSON。
- `ModeController.current` 是单个字符串，`colors` / `levels` 靠整体替换 dict
  引用，CPython 属性赋值原子，HTTP 线程写 / 主循环读都不用锁。接口
  `/api/setcolor?mode=&hex=`、`/api/setlevel?mode=&level=`、`/api/resetcolor?mode=`
  （路径名沿用历史，语义已扩展为恢复该模式的默认颜色 + 默认强度），
  `/api/status` 下发 `colorModes` / `decorModes` / `defaultColors` / `colors` /
  `levels` / `defaultLevel`。

### 亮度：只在固件限一次

60 颗全白理论 3.6A，**唯一的亮度硬限在固件**：v6 的 `BRIGHTNESS_CAP = 128`
（`strip.setBrightness()` 50%），host 发 255 也只到 128。Python 端**不再二次打折**：
装饰帧 `_idle_tone()` 输出 0~255 全范围，`raw=True` 直出绕过 gamma 与
`--max-level`。固件 `CMD_BRIGHTNESS` 的注释本来就写着「只 clamp 这一处，
不再叠加别的折扣，避免两道相乘把亮度压没」。

旧版曾在 host 又压一道 `IDLE_PWM_CAP = 48`，两道相乘后实际只剩 24/255。
更严重的是 `_idle_pwm()` 按**每颗灯的峰值**归一化，把亮度系数整个约掉：
`c*k ≡ base*48/max(base)`，与 `lv` 无关。于是呼吸灯 4 秒里 3.2 秒恒为
`(48,35,26)`，波浪 / 火焰 / 星空 / 跑马灯所有时刻 60 颗全亮、峰值恒 48，
彗星头几颗也全同亮 —— 亮度变化不明显、整条都亮，都是这一个 bug。

现在**颜色与亮度线性相乘**：`base × lv`，不放大也不改色相 —— 若按峰值
归一化到 255，用户选的 `#101010` 会被拉成满亮白，自定义颜色就没意义了。
明暗 1:1 落到颜色值上，前端预览与实机逐通道对得上。同时重做了几条曲线：
呼吸下限压到 0.03、波浪 `w^1.7` 拉开波峰波谷、
**彗星用整数颗 + 环绕**：`head = 59 - (int(t/0.075) % 60)`，
`k = (led_i - head) % 60`，只有 `k < COMET_TAIL_LEDS(10)` 的灯亮 ——
**任何时刻恰好 10 颗**（头 1 + 拖尾 9），头走到第 0 颗后下一帧回到第 59 颗，
尾巴环绕到近端，全程无缝没有空窗。亮度按几何级数 `lv = 0.5^k`
（100% / 50% / 25% / 12.5% … 第 11 颗归零），旧的线性 100%→30% 前几颗差别
太小、看着一片同亮，已弃用。颜色按 `k/9` 让绿/蓝比红衰减更快，
尾巴渐变到「燃尽」的暗红焦色。
前端 14 颗预览按 `round(i×59/13)` 映射回 60 颗坐标，比例一致。
旧的连续相位版亮区最多 42 颗、头还会划出灯带留下整条空窗，已弃用。
**火焰改成空间+时间连续的三层正弦噪声 + 2.4s 火势起伏**（火苗高度包络），
不再是每颗独立随机的橙色点点；星空暗档严格 0 且只留约 15% 星点、
跑马灯改满亮饱和色块 + 短暗缝（低 PWM 会把色块压成灰，就是「饱和度不对」
的观感来源）。

实测：彗星在整圈 60 个时刻里**每次都恰好 10 颗亮**，头位置 59→0→59 无缝衔接，
尾巴 R/G 比随距离单调上升（越往后越红）；火焰总亮度在 1431~4671 之间起伏
**69%**、火苗高度 16~53 颗、相邻灯珠平均跳变仅 4.1（连续而非随机）；
呼吸一周期 8→255、波浪 5→255 且 18 颗近灭、星空仅 12 颗亮。

**供电提醒**：host 端所有亮度上限都放开后（装饰帧 + 放歌封面 + 环境彩虹），
白色封面满档 / 白色装饰常亮 / 60 颗 VU 满档都逼近
`60 × 60mA × 0.5 ≈ 1.8A`（VU 80% 约 1.44A），对 5V 2A 电源余量不大，
**建议外接 5V 3A**。装饰模式默认强度 **50%**（约 0.9A），面板
「整体强度」滑块可在 10%~100% 之间拖高或拖低（只缩不放，100% 才会吃满 1.8A）。
放歌 / VU 目前没有独立强度旋钮。
当前只有一条 v6 灯带，亮度上限统一由固件 128 硬限。

复用现有 50Hz 主循环，装饰态走 12ms 颜色平滑（150ms 会把流动颜色糊成一团），
几乎零额外开销。

`--panel-port 51876` 改端口、`--no-panel` 关掉面板（只剩文件切换）、
`--idle-mode rainbow` 指定启动初值（文件存在时以文件为准）。

## 封面取色：60 颗连续渐变

采的是 **60 个颜色**，每颗灯珠一个 —— 相邻两颗之间平滑过渡，
v6 固件逐颗直接写入，不再有「2 颗同色」的台阶。

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 细列加权平均 | 封面缩到 480×48，横向 480 条细列，每列按 `(0.25+0.75s)×(0.35+0.65v)` 加权平均 | 取代旧的「每列量化取主色」：主色是离散簇，相邻列容易选中不同颜色，60 颗上就是一排硬边界；加权能压住大面积黑背景，不把颜色冲成灰 |
| 三角核平滑 | 半径 3 颗（24 细列），中心权重最大、向两边线性递减，端点按实际权重归一化 | 相邻灯珠共享大半像素，一个硬边界被摊到约 6 颗灯 |
| 组内降采样 | 每 8 条细列平均成 1 颗 | 抗锯齿，得到 60 颗 |
| 明度归一化 + 再抹一遍 | 沿用 `_normalize_values()`，之后再过一次 1 颗半径的三角核 | gamma / `v_floor` 是逐色非线性映射，会在暗处留折点；抹掉让变化率也连续 |

实测（左红 / 黑竖带 / 右蓝的极端合成封面），**相邻灯珠最大通道差**：

| | 最大 | 均值 |
|---|---|---|
| 旧逐列主色 | 220 | 15.2 |
| **新渐变（60 颗）** | **53** | **6.6** |

首尾仍是 `(230,31,31)` / `(31,84,230)`，**封面左右的空间对应没有丢**，
中间出现多级过渡色而不是两色硬切；真实暗封面测得的相邻差更小（约 20 上下）。

**去黑回填也跟着改了**：旧版按位置轮转从候选池取色，会在渐变里凭空插进一个
跳变；现在用左右最近非黑颜色的**线性插值**填黑位，拿到的正好是两侧过渡色。
`--cover-layout weight` 也从「主色连续占 N 组」的硬分段改成把配色当色标插值，
两种布局都保证 0 黑灯。

**九宫格配色的上限是 10 色**（`analyze_cover(top=10)`）：它只用作
`--cover-layout weight` 的插值色标和面板「配色」行；`spatial` 布局走的是
上面那套 60 颗细列渐变，不受这个数限制。封面本身颜色少时自然少于 10 色，
不补重复色。配色行的色块会按面板宽度自动收紧，不会撑破边框。

旋钮是文件头常量：`COVER_SMOOTH_GROUPS`（默认 3.0，越大越糊）、
`COVER_FINAL_SMOOTH`（默认 1）、`COVER_OVERSAMPLE`（默认 8）。
同一张封面两次计算结果完全一致，切歌不会闪。

> **v6 已实现逐颗独立控色**：host 发 180B，固件第 i 颗直接用 `payload[i*3..]`，
> 不再有「相邻 2 颗同色」的台阶。代价是帧长翻倍到 185B，50Hz 下占 80.3% 带宽，
> 帧率不能再往上提（100Hz = 160% 会超）。
