# 音乐封面呼吸灯（WeMOS D1 mini + 8 颗 WS2812B）

把 D1 mini 变成一盏会看场合的灯，两件事，按优先级：

1. **有音乐在播** —— 认出电脑上正在播放的音乐，把专辑封面解成配色铺到 8 颗灯珠上；
   **亮几颗、多亮由系统输出设备的实时峰值决定**（读的是正在播放的声音，不是麦克风），
   颜色仍是这 8 颗封面配色，**采样到黑色时会用同一张封面的其它颜色回填，不会出现黑灯**。
   **真静音一颗都不亮，极小声从 1% 亮度起步**；
   输出端点读不到峰值时才降级回整条呼吸。
2. **没在播音乐** —— 麦克风没被占用时**灯带全灭、板载 LED 也灭**，完全静默；
   麦克风一被占用，板载 LED **常亮**，灯带变成一条 **100Hz 的电平表**：
   音量同时决定 **亮几颗**（1~8，从离板子最近的那颗往最远的长，**lv=1.0 才满 8 颗**）、
   **什么颜色**（绿 → 黄 → 橙 → 红）和 **多亮**（最终占空比 1% → 80%）；
   **没声音或声音极低时一颗都不亮**。

**降级封面呼吸**受 `--max-level` 的 70% 上限限制；**两种声音驱动灯效是例外**
（放歌封面灯 / 麦克风 VU），它们按最终 PWM 占空比直出（否则 1% 过 gamma 会全黑）。

**板载 LED（GPIO2 / D4）兼两职**：常驻状态（未占用熄灭 / 占用常亮）+ 事件脉冲
（切歌闪 2 下、状态切换闪 3 下）。麦克风关闭就熄灭（详见「板载 LED」一节）。

**设计原则：智能全在电脑端，ESP8266 只当哑终端。** 改配色、换声音数据源、调映射都不用重新烧录。
唯一例外是板载 LED 的失联提示 —— 那时候串口已经断了，电脑根本发不出命令，只能由固件自己判断。

> 本项目早期做过节拍闪烁（BPM 预测 + 起音跟随）、人工打拍子、GPU 占用条、CPU 进度条、
> 麦克风「整条绿/整条橙」的二值指示，以及「没播音乐时跟屏幕画面走」的抓屏氛围光，
> 这些都已**全部移除**，代码也删干净了。`host/` 下只有 `led_host.py` 一个脚本
> （采集、配色、输出峰值、麦克风占用/电平、面板、串口输出都合并在里面）。
>
> 抓屏氛围光是最后一个被砍的，原因是它两头不讨好：独占全屏的游戏（地平线 5、赛博朋克 2077
> 默认都是）画面不进桌面合成器，GDI 抓到的是纯黑，灯反而灭掉；而 GDI 从桌面 DC 回读
> 2560×1440 一次要 16ms，5Hz 抓屏就要吃掉单核 8%。麦克风检测只读注册表 + 一个系统峰值接口，
> 单次不到 0.1ms，跟画面怎么输出毫无关系。

## 硬件

| 项 | 值 |
|---|---|
| 数据脚 | **GPIO4（D2）** |
| 灯珠 | 8 颗 WS2812B |
| 板载 LED | 开发板自带的蓝色 LED，**GPIO2（D4）**，低电平点亮，用作麦克风状态指示 + 事件提示 |

三个必须注意的点：

1. **别用 GPIO0。** 它是 ESP8266 的 strapping 引脚，上电被拉低会让芯片进 UART 下载模式、固件根本不跑（症状：插上灯不亮，重新烧录又能亮）。灯带掉电/上电时序错开时，DIN 的 ESD 二极管会倒灌把它拉低。GPIO4 没有这个问题。
2. **电平匹配。** ESP8266 是 3.3V，WS2812B 在 5V 供电下要求高电平 ≥3.5V，3.3V 直驱属于擦边球——短距离能亮，但换灯带或温度升高后会首灯错色。正解是 74AHCT125/74HCT245 做电平转换；省钱解是给灯带串一只 1N4001 把 5V 降到约 4.3V，阈值随之降到 3.0V。
3. **供电。** 8 颗满亮约 480mA，加板子自身已逼近 USB 500mA 上限，会触发过流重启（表现是灯闪一下全灭）。所以降级封面呼吸压在 `--max-level 0.70`，声音驱动灯效另有限幅（见「亮度」一节）；灯带最好单独 5V 供电、与板子共地不共 5V。灯带 VDD/GND 并 100~470µF 电容，DIN 串 330Ω 电阻。

## 快速开始

### 1. 装依赖

```
cd host
pip install -i https://mirrors.aliyun.com/pypi/simple -r requirements.txt
```

**别用清华源**：清华源的 `winrt-*` 只有 `2.0.0b1` 预发布源码包，pip 默认跳过预发布，会报 `Could not find a version (from versions: none)`。

**别装 `winsdk`**：那个包已废弃，最后版只支持到 Python 3.12。

### 2. 烧固件

Arduino IDE 正常烧 `ESP-WS2812.ino`，板子选 `LOLIN(WEMOS) D1 R2 & mini`。烧完板载蓝灯连眨 3 下表示固件跑起来了。

命令行编译（可选）：

```
"C:\Users\yoea\AppData\Local\Programs\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe" compile --config-file "C:\Users\yoea\.arduinoIDE\arduino-cli.yaml" --fqbn esp8266:esp8266:d1_mini "D:\Develope\esp8266\3.WeMOS D1 mini\ESP-WS2812"
```

必须带 `--config-file`，否则找不到库（sketchbook 在 `D:\Develope\Arduino`，不是默认的 Documents\Arduino）。

### 3. 跑

```
python led_host.py                       # 默认：封面配色 + 系统播放峰值驱动
python led_host.py --list-ports          # 确认串口号
python led_host.py --demo                # 灯带自检
python led_host.py --diagnose            # 体检媒体源 / 麦克风
python led_host.py --autostart install   # 装成开机自启的后台常驻（见下节）
```

## 开机自启 / 后台常驻

```
python led_host.py --autostart install   # 装：以后每次登录 Windows 自动在后台跑，没有窗口
python led_host.py --autostart status    # 看：装没装、在不在跑、上次什么时候跑的、日志在哪
python led_host.py --autostart start     # 立刻启动一次（不用等下次登录）
python led_host.py --autostart stop      # 临时停掉（灯熄灭；不卸，下次登录还会起来）
python led_host.py --autostart remove    # 彻底卸掉自启
```

第一次 `install` 会弹一次 UAC —— 注册计划任务需要管理员。装好后在
**任务计划程序库**里有一个叫 **`ESP-WS2812 音乐封面呼吸灯`** 的任务，点开它的「描述」
写着它是干嘛的、日志在哪、怎么停怎么卸，忘了的时候看那一栏就行。

自带三件事：登录后 **20 秒**才启动（等 USB 枚举完）、串口没就绪会**最多等 30 秒**、
进程意外退出会**自动重启 3 次**（每次间隔 1 分钟）。

### 为什么是任务计划程序，不是 Windows 服务

服务一律跑在 **Session 0**，跟登录进来的桌面会话是隔离的。本程序靠 SMTC
（系统媒体传输控制）读「正在放什么歌」，而 SMTC 是按用户会话枚举的 —— 在 Session 0 里
拿到的会话列表恒为空，灯会永远不亮，等于白装。

任务计划程序的进程跑在用户会话里，媒体源正常，同时也有服务的三样好处：
开机自启、无窗口、失败自动重启。所以它是这里的正解。

### 后台运行时怎么排查

界面全部关闭，输出只进 `host/logs/led_host.log`（超过 1MB 自动滚成 `.old`）：

- 每次启动写一行 `--- 后台启动 ---` 加完整命令行；
- 切歌写一行 `[media] 歌名 — 歌手`，停了写 `[media] （没在播放）`；
- 串口断开/重连也都在里面。

灯不亮时先看这个日志，多半一眼能看出来是串口没连上还是媒体源没读到。

### 装不上时的降级方案

UAC 被取消、或者机器上根本没管理员权限时，可以用不需要管理员的「启动文件夹」方案：

```
python led_host.py --autostart install --method startup
```

它往「启动」文件夹放一个 `ESP-WS2812 音乐封面呼吸灯.vbs`（UTF-16，开头有中文注释说明
用途和关闭方法），效果一样，只是少了「崩溃自动重启」。两种方式互斥，装了前者会自动清掉后者。

## 灯效一：封面配色 + 系统播放峰值

| 条件 | 状态 | 表现 |
|---|---|---|
| 有音乐在播 | `media` | 8 颗铺封面配色，**亮几颗 / 多亮由输出峰值决定** |
| 输出端点不可用 | `media` | 降级：8 颗铺封面配色，整条同步呼吸（旧灯效） |
| 停了 1.5 秒以上 | 交给麦克风电平表 | 见下 |

### 声音从哪来

**不开麦克风**，读默认输出设备的 `IAudioMeterInformation::GetPeakValue`：
和麦克风 VU 同一份 `ctypes` COM 代码，只是 `GetDefaultAudioEndpoint` 从
`eCapture/eMultimedia` 换成 `eRender/eConsole`。也就是 Windows 音量条旁边
那个绿色跳动条的数据 —— 系统播放混音的瞬时峰值。

好处：纯数字信号，**戴耳机照样亮**；你说话、敲键盘、环境噪音都不会带偏灯；
不开任何捕获流，完全不碰 ConsentStore，麦克风占用判定不受影响。
代价：拿到的是**默认输出设备的混音**，不是当前播放器单轨 —— 游戏音效、
系统提示音也会算进去（用 SMTC「正在放歌」当开关，实际场景基本就是音乐）。
少数独占模式播放器 / 部分声卡驱动对输出 meter 支持差，读不到时自动降级回呼吸。

### 映射

峰值按固定量程归一化成 `lv = peak / RENDER_FULL_PEAK`（数字输出没有底噪，
静音就是 0），颗数复用 `1 + lv×7`（lv=1.0 才满 8 颗）。唯一区别是颜色：
不用绿→黄→橙→红，而是每颗用**自己那个位置的封面色**
（`base[idx]`，保持灯带位置 ↔ 封面左右的对应）。

**封面色必须先逐通道过 gamma 再乘亮度**：`gamma_base = apply_gamma(base)`，
然后 `out[idx] = scale(gamma_base[idx], render_brightness(lv))`。
这一步不能省 —— 直接拿感知 RGB 乘系数再 `raw` 直出，亮通道被拉满、
暗通道也被一起抬起，看起来就是一片过曝的白。过完 gamma，
最亮的白色封面约 **94/255**，正好等于旧封面呼吸的 `gamma(255×0.70)=93`；
橙色封面 `(255,100,50)` 得到 `(94,7,1)`，旧灯效最亮是 `(93,7,1)` ——
观感与「采样专辑封面」保持一致。
亮度系数由 `render_brightness()` 给出：`RENDER_BRIGHT_FLOOR = 0.01`（1%）
到 `RENDER_BRIGHT_MAX = 0.37`（37%）**线性插值**，全程随 lv 连续变化。
1% 是曲线的**起点**，不是「低音量段固定不变」的保底平台 ——
之前那种固定 5% 平台才会被看成「声音很小灯却很亮」。
白色封面的峰值：lv 0 / 0.05 / 0.1 / 0.5 / 1.0 → 约 2 / 7 / 11 / 48 / 94（单位 /255）。

**真静音全灭，极小声才从 1% 起步**：数字输出没有底噪，静音时端点峰值精确为 0。
`peak < RENDER_SILENCE_GATE = 0.005` 时**一颗都不亮**（靠 0.035s 平滑柔和淡出）；
刚过门限才走 `1 + lv×7`，至少 1 颗、1% 亮度约 2/255，声音稍起来就连续变亮。
这样「完全没声音」和「有一点声音」分得开，也不会出现静音时第一颗常亮。
它不套麦克风 VU 那个 0.02 门限（那边有底噪、量程也不一样）。最后一颗仍按小数渐入，
但**只在已经亮了 2 颗以上时才渐入** —— 否则唯一那颗会被小数系数削暗，
出现「音量变大反而更暗」的忽明忽暗。

**极暗封面色的色相保底**：封面左列若是深色，过 gamma 后可能只剩 `(0,1,4)`，
再乘低亮度系数会被 `int` 截断成 `(0,0,0)` —— 逻辑上点亮了、肉眼却看不见，
表现为「第二颗亮、第一颗灭」。`with_glow()` 按它自己的色相比例补一丝微光，
**只作用于已点亮的灯珠**；亮色灯珠和熄灭的灯珠都不动。
保底强度**跟着亮度走**：`RENDER_MIN_GLOW × bright / RENDER_BRIGHT_MAX`，
静音侧约 1/255、满档 3/255。不能用固定 3/255 —— `(0,1,4)` 的最大通道只有 4，
乘满档系数 0.37 也到不了 3，会让深色封面从 lv=0 到 1.0 全程锁定在同一个输出，
又变回「固定平台」。

声音驱动都按最终 PWM 直出（`set_all(raw=True)`；gamma 已在 `gamma_base` 做过一次，
不能再过第二遍）；颜色平滑用 0.035s 跟波形。
原来的 4 秒整条呼吸已取消（两套驱动会打架），只在降级路径保留。

**校准**：播放一首常听的歌，跑 `python led_host.py --render-calibrate`，
它打印最大/平均输出峰值并给出建议的 `--render-full-peak`。
本机实测（普通音量播放）：最大约 **0.49**、平均约 **0.22**，脚本建议 0.48；
默认 1.00 更保守、灯会偏少，想更活跃就按建议值调小。
要让自启也用这个值，重跑 `--autostart install` 固化参数。

切歌/暂停会有零点几秒没有 `Playing` 的空档，所以切走留了 **1.5 秒缓冲**（`MEDIA_FALLBACK_DELAY`），不然每次切歌灯都要闪一下。

## 灯效二：麦克风电平表（没播音乐时）

| 麦克风状态 | 亮几颗 | 颜色 | 亮度（最终 PWM 占空比） |
|---|---|---|---|
| 没被任何程序占用 | **0 颗（全灭）** | —— | 板载 LED 也灭，完全静默 |
| 正在用，没声音 / 声音极低 | **0 颗（全灭）** | —— | 声音门限以下不亮 |
| lv = 0.1 | **1.7 颗** | 绿 | **1%** |
| lv = 0.3 | **3.1 颗** | 绿 → 黄 | **19%** |
| lv = 0.5 | **4.5 颗** | 黄 → 橙 | **36%** |
| lv = 0.7 | **5.9 颗** | 橙 | **54%** |
| lv = 1.0 | **8 颗** | 末端红 | **80%** |

**颜色按亮起顺序分段**：第 1 颗绿(120°)，线性过渡到黄(60°)、橙(30°)，第 8 颗红(0°)。
**点亮方向从最近端往最远端**：WS2812 帧里 index 0 是数据线进来的第一颗（离板子最近），
index 7 是灯带末端（最远），所以默认按 `0 → 1 → … → 7` 长。
`--mic-reverse` 翻回 `7 → … → 0`。

### 音量怎么同时控制三件事

`MicLevel` 把设备峰值归一化成 `lv`（0~1），再走两条独立曲线：

| lv | 0 | 0.02 | 0.10 | 0.30 | 0.50 | 0.70 | 0.90 | 1.00 |
|---|---|---|---|---|---|---|---|---|
| 颗数（`mic_led_count`） | 0 | 1.1 | 1.7 | 3.1 | 4.5 | 5.9 | 7.3 | 8.0 |
| 亮度（`mic_brightness`） | 0% | 0% | 1% | 19% | 36% | 54% | 71% | 80% |

两处关键：
- **声音门限 `MIC_SOUND_GATE = 0.02`**：麦克风虽然被激活，但没声音 / 声音极低时
  `mic_led_count()` 直接返回 0，8 颗全灭；只有真检测到声音才亮起来。
- **`lv=1.0` 才满 8 颗**：颗数按 `1 + lv×7` 线性长，亮度按 `MIC_BRIGHT_STOPS`
  从 lv=0.1 的 1% 走到 lv=1.0 的 80%。8 颗灯覆盖整个电平范围，不会提前到顶。
  旧的「lv≥0.70 就 8 颗、之后只加亮度」已取消 —— 那正是贴嘴说话一下打满的原因之一。

亮度按 `MIC_BRIGHT_STOPS` 分段线性插值，单调递增；最后一颗按小数渐入，不是硬跳档。
不是频谱、也不是硬跳的档位：100Hz 下看起来是连续的 VU 条。
**只有电平表**的颜色平滑单独用 **0.035s**（其余态 0.15s），否则低通会把波形削平；
待机用 0.15s 还能让「录音结束 -> 全灭」的收尾更柔和。

### 「谁在用」和「声音多大」是两件事

**谁在用** —— 读 Windows 隐私同意记录：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\
    ConsentStore\microphone
    ├─ <打包应用包名>\LastUsedTimeStart / LastUsedTimeStop
    └─ NonPackaged\<Win32 路径，反斜杠写成 #>\...
```

每个真的打开过麦克风捕获流的进程都有一对 FILETIME（1601 起算的 100ns 计数），
**`Start > Stop` 就是「这个进程正在录音」**。任务栏那个「麦克风正在使用」小图标
用的也是这份数据。只用标准库 `winreg`，一次扫几十个子键不到 1ms。

**声音多大** —— 读 WASAPI 的 `IAudioMeterInformation::GetPeakValue`，也就是
Windows 音量条同款的**设备级峰值**（0~1）。它**不打开捕获流**，这一点是关键：
如果为了拿音量自己起一路录音（ffmpeg / pyaudio 都行），那个进程会把自己写进
ConsentStore，于是「麦克风没在使用」永远不成立，待机（全灭 + 板载闪）就再也回不去了。
峰值表只读设备，注册表判定保持干净。用 `ctypes` 手写 COM vtable 调用，
**零第三方依赖**（不需要 pycaw / comtypes / numpy / pyserial 之外的任何东西）。

> 接口 IID 是 `C02216F6-8C67-4B5B-9D00-D008E73E0064`。
> 网上常见的 `…D01E1FE83D21C` 是错的，`Activate` 会直接回 `E_NOINTERFACE`。

**实测**（本机 Realtek 麦克风，ffmpeg 模拟他人录音 + 播放 440Hz 测试音）：

| 场景 | 设备峰值 |
|---|---|
| 没有任何程序捕获 | **恒 0.0000**，播放声音也是 0（设备没上电） |
| 有程序捕获、安静 | 0.0066 ~ 0.0105（底噪） |
| 有程序捕获、出声 | 0.104 ~ 0.108（**10 倍**），响应 <0.25s |
| 6 秒音量线性渐大 | 0.009 → 0.083 单调递增，归一化后 1~8 档全覆盖且分布均匀 |

单次 `GetPeakValue` 实测约 **41 微秒**，整帧纯计算约 59µs，100Hz 采样占 CPU 约 **0.6%**。
额外好处：peak 恒 0 可以当「没人在用」的交叉验证，还能识破注册表里的僵尸记录。

### 电平归一化：固定量程，别让满档跟着声音跑

早期这里用过「滚动峰值参考」，结果是个真 bug：`peak` 一超过参考值就立刻把参考
抬到 `peak`，于是 `target = (peak-floor)/(ref-floor) = 1.0` —— **任何正常说话都会
直接算成满档 8 颗**，只有压低声音、等参考衰减下来才会回到 1~2 颗。

现在量程固定不动：

- `lv = clamp((peak - 0.006) / (MIC_FULL_PEAK - 0.006), 0, 1)`，
  `MIC_FULL_PEAK` 默认 **1.00**，即吃满 WASAPI peak 的整个 0~1 物理范围。
  旧默认 0.35 只用了 1/3 量程，再叠加「lv≥0.70 就 8 颗」，实际 peak≈0.25 就到顶 ——
  **不是麦克风动态范围低，是两道提前封顶叠在一起**。
- 新映射实测：peak 0.10 → lv 0.095 → **1.7 颗 / 1%**；
  peak 0.50 → lv 0.497 → **4.5 颗 / 36%**；peak 1.00 → **8 颗 / 80%**。
- 量程不会被声音撑大，响度关系稳定；电平本身再做 0.035s 快平滑，跟手但不抖。
- **实测自己的峰值**：先让一个应用占着麦克风（系统录音机 / 语音输入法 / 会议软件），
  再跑 `python led_host.py --mic-calibrate`，用正常音量说 5 秒，
  它会打印最大 peak 和建议的 `--mic-full-peak`。脚本只读设备峰值、不开捕获流，
  不会污染注册表判定。要让自启也用这个值，重跑 `--autostart install` 固化。
  若贴嘴说话 peak 已经是 1.0（削波），量程没得再放大，得去系统里调低麦克风增益。

### 两个必须处理的坑

- **输入法 / 语音助手的短脉冲**：本机记录里 DoubaoIME、千问输入法、微信、Typeless
  都开过麦克风，最短的一次只有 **75ms**。若直接按 `Start > Stop` 亮灯，会莫名其妙跳档。
  所以加了双向去抖：连续在用 **0.2s** 就认（注册表每 **0.05s** 扫一次，
  最坏约 **0.25s** 出灯；0.2s 仍大于那 75ms 的短脉冲，不会误触发），
  连续空闲仍要 **1.5s** 才放开，免得说话中的停顿让灯来回跳。
- **进程崩溃残留**：被强杀的进程不会写 `Stop`，`Start > Stop` 会永远成立。
  所以 **超过 6 小时**的 `Start` 一律当成僵尸记录忽略；peak 恒 0 也能辅助识别。

`python led_host.py --diagnose` 会列出当前判定、正在使用的应用、最近 8 条访问记录、
设备峰值、固定量程与声音门限，以及 8 档「颗数 / 亮度」电平预览。
接好麦克风后跑一次就能确认检测正不正常。

> 早期这里先是 **CPU 占用进度条**，后来改成「整条绿 / 整条橙」的二值指示，
> 都已按需求完整移除，相关代码也删干净了。

## 板载 LED：麦克风状态 + 事件脉冲 + 失联呼吸（GPIO2 / D4）

D4 上这颗开发板自带的蓝色 LED（低电平点亮）。现在**只在麦克风被占用时常亮**，
其余时间一律熄灭 —— 待机时灯带和板载灯全灭，完全静默。

| 板载 LED | 含义 | 谁决定 |
|---|---|---|
| **灭** | **麦克风没被占用**：待机静默，灯带也全灭 | 电脑端 |
| **常亮** | **麦克风正在被占用** | 电脑端 |
| **闪 1 下** | **封面/SMTC 信息真正取到**：封面字节 MD5 变化、取色更新完成 | 电脑端 |
| **闪 2 下**（亮 90ms / 灭 130ms） | **切歌了**：曲目标题或歌手变了（**不代表封面已到**） | 电脑端 |
| **闪 3 下** | **灯效状态切换**：放歌 ↔ 麦克风态 ↔ 熄灭 | 电脑端 |
| **温柔呼吸**（PWM 渐亮渐暗，2.6s 一个来回） | **主机失联**：USB 线断了 / 电脑关机 / 后台服务崩了 | 固件自己判断 |

麦克风一关闭就熄灭，不用重启服务。状态只看「有没有程序在用麦克风」，与放不放歌无关。
要整块关掉（连事件脉冲一起）用 `--no-status-led`。

### 封面就绪为什么要单独报一声

SMTC 的**标题**和**封面**不是同时更新的：网易云这类播放器切歌后标题立刻变，
封面可能滞后好几秒才到。原来的「闪 2 下」只代表标题变了，你没法知道
灯效什么时候才真正用上新封面。现在 `MediaWatcher` 在封面字节 MD5 变化、
`_set_palette()` 完成的那一刻把 `cover_updates` 加一，板载 LED 闪 **1 下**报「就绪」。

**只在封面明显滞后于切歌（≥ `PULSE_GUARD` 0.8 秒）时才补这一下**：
快速切歌时「2 下」已经代表封面也到了，再补 1 下既冗余，
两条 `0x08` 又会在固件里互相覆盖（后一条会重置前一条的脉冲）。
所以网易云的典型节奏是「先 2 下，过几秒再 1 下」，一眼就知道什么时候拿到了。
若两张封面字节完全相同（同一张专辑换曲目），MD5 不变、取色本来就不更新，
也就不会闪这 1 下。

### 实现

host 只在状态翻转时发一条 `0x07`（`set_status_led` 带缓存）：`0`=灭、`1`=常亮。
固件里的 `2`=慢闪是 0.5Hz，用不上，所以**固件不用改、不用重烧**。
事件脉冲走 `0x08`，每帧最多一条（固件收到第二条会覆盖第一条）：
状态切换 > 切歌 > 封面就绪。连续脉冲有 0.8 秒冷却。
「待机 ↔ 录音电平表」只是 `mic` 态内部换灯效，`state` 没变，不闪事件脉冲
（常驻状态自己会从灭变成常亮）。**电平档位变化不发脉冲**：
100Hz 下一秒钟能变十几档，再让板载灯跟着闪就变成频闪灯。

### 失联为什么是呼吸

失联时灯带熄了、板载灯也灭了，跟正常待机看起来一样；
所以固件在 3 秒无数据后自己接管，用温柔呼吸把「出事了」和「正常待机」区分开。
用呼吸而不是快闪是刻意的：它表示「我在，等你回来」，而不是「坏了，快来看」——
电脑关机本来就常态操作，没必要报警。峰值亮度也只到 55%，不刺眼。

判断逻辑是「超过 3 秒没收到任何一帧，**而且**主机最后一条命令不是 `OFF`」。所以：

- Ctrl+C 正常退出（先发 `OFF`）→ 灯安静地灭着，不呼吸；
- 进程被强杀 / 拔线 / 关机 / 休眠 → 进入呼吸。

上电后主机一直没连上，3 秒后也会呼吸 —— 那是在说「固件在跑，但没人在推数据」，
**不是板子坏了**。

进入呼吸会等灯带渐灭走完再开始（约 3 秒），所以从拔线到看见呼吸大约 6 秒。
这个先后顺序不能反，理由见下。

### 这里为什么敢用 `analogWrite`

早先明确说过「只用 `digitalWrite` 开关、不上 `analogWrite`」，理由是 ESP8266 的 PWM
靠定时器中断实现，会打断 WS2812 的软件位翻转。这次能破例，是因为**用它的时机变了**：

呼吸只在「主机已经不发数据」的窗口里启用。这段时间里 `strip.show()` 一次都不会调用，
**没有位翻转，也就没有可被打断的时序**。

代价是必须守住两条纪律，代码注释里都标了：

1. 进入呼吸前先等灯带渐灭走完 —— 渐灭里有 `show()`，不能和 PWM 并存；
2. `handleFrame()` 第一件事就是退出 PWM —— 收到任何一帧立刻把引脚交还给 `digitalWrite`，
   否则那一帧的 `show()` 正好会被打断。

其余场景（开机自检、事件脉冲）仍然只用 `digitalWrite`。

顺带一提，GPIO2 是 ESP8266 的 strapping 引脚之一，但板载 LED 是低电平点亮 + 板上外部上拉，
**上电时是高电平（灭）**，不会把芯片拖进下载模式 —— 可以放心用。

```
python led_host.py --no-status-led    # 整块关掉（GPIO2 要接别的东西时才用）
python led_host.py --demo             # 自检时依次演示「闪 2 下」「闪 3 下」
```

## 亮度：降级呼吸 70% 上限，声音驱动走自己的曲线

降级路径的封面呼吸受 **70%**（`--max-level 0.70`）限制，在 **gamma 之前**乘到每颗灯上
—— gamma 是「感知亮度 → PWM」的映射，乘在前面才是真的把亮度降到 70%；
乘在后面等于把 PWM 砍掉 70%，会暗得多。
70% 感知亮度对应 PWM `gamma(178) = 93`，8 颗约 173mA，加板子约 250mA，离 USB 500mA 还有余量。

**两种声音驱动灯效是例外**（放歌封面灯 / 麦克风 VU）。它们要表达 lv=0.1 的 1%
到 lv=1.0 的 80% 这种**最终 PWM 占空比**（和你最早那颗「10% 绿灯」同一口径）；
放歌另把封面色先过 gamma，再用 `render_brightness()` 映射到 1%~37% 的 PWM 系数
（最亮白色封面约 94/255，与旧封面呼吸一致）。
如果再走一遍 `gamma(i)=255*(i/255)^2.8`，10% 会被压到约 0.4/255、1% 直接是 0，
低音量段全黑，亮度维度就废了。所以 `mic_leds()` / `media` 分支直接算好最终 PWM 值，
`LedStrip.set_all(..., raw=True)` 原样发出，绕过 gamma 和 `max_level`。

80% 会不会过流？VU 用的是饱和单色（绿/红一通道、黄/橙两通道），不是白色三通道全开，
8 颗约 200~260mA，仍低于「8 颗全白满亮」的约 480mA。
**放歌时更要注意**：封面色可能是白色/浅色，所以先逐通道过 gamma（避免泛白过曝），
且亮度系数上限只有 `RENDER_BRIGHT_MAX = 0.37` —— 最亮白色封面约 94/255，
与旧封面呼吸相当，不会打穿 USB 500mA。
接在 USB 口上若仍出现过流重启，把 `MIC_BRIGHT_STOPS` 末锚点或 `RENDER_BRIGHT_MAX` 调低。

`--brightness`（固件侧）默认满档，不再二次打折：**两道相乘会把 70% 压成 37%**
（`128/255 × 0.70`），灯肉眼可见地偏暗。降级呼吸调 `--max-level`，
声音驱动灯效调 `MIC_BRIGHT_STOPS` / `render_brightness()`，各管各的。

### 降级呼吸怎么算（输出端点不可用时）

正常放歌已改由输出峰值驱动，下面的余弦呼吸**只在默认输出设备读不到峰值时启用**。
亮度在一个周期内按余弦平滑地「最暗 → 最亮 → 最暗」往返：

```
phase = (now % period) / period
wave  = 0.5 − 0.5 × cos(2π × phase)          # 0 → 1 → 0
level = (1 − depth) + depth × wave            # 落在 (1-depth) ~ 1
```

用 `cos` 而不是 `sin`，是为了从"最暗"起步 → 慢慢亮起来，起始手感更自然。
默认 `period = 4.0s`（0.25Hz，和原来的 `breathe` 灯效一致）、`depth = 0.40`
（亮度在 `0.60 ~ 1.00` 之间起伏）。

呼吸是连续函数，本身已经平滑，所以输出**不做额外插值**——只有换歌时颜色突变才用
0.35s 时间常数（`SMOOTH_TAU`）柔化过渡，避免颜色"啪"地换掉。

### 封面取色方式

`--cover-layout` 二选一：

| 方式 | 表现 |
|---|---|
| `spatial`（默认） | 把封面按水平方向切成 8 条，每列取主色，**灯珠 i 对应封面第 i 列**——灯带从左到右就是封面从左到右。左红右蓝的封面，灯带就是左 4 颗红、右 4 颗蓝 |
| `weight` | 用九宫格算出带权重的多色，按权重铺到 8 颗灯上（权重大的颜色占多颗），呈现的是这张封面的**配色比例**而不是空间位置 |

两种方式都保留明度维度：暗的那几颗灯真的更暗。

### 去黑回填：8 颗里不允许出现黑灯

以前黑色会被当成一种合法配色分给灯珠：`_dominant()` 只丢纯黑（`v<0.02`），
整列全黑时直接返回 `(0,0,0)`；`_normalize_values()` 的 `v_floor=0.15` 又把它
抬成 `(38,38,38)` 灰，看着不是黑，过 gamma 却只剩 `(1,1,1)` —— 那颗灯逻辑上
点亮了、肉眼完全看不见。**黑×2 / 蓝×2 / 红×2 / 绿×2** 的封面实测就有 **2 颗黑灯**。

现在在 `_cover_base()` 生成最终 8 颗后统一过一遍 `fill_dark_leds()`，spatial / weight
两条布局都覆盖，原来的九宫格量化与打分逻辑一行不动：

- **判据**（`is_black_led`）：`max(apply_gamma(c)) < 8/255` **且** HSV 饱和度 `s < 0.30`，
  也就是「最终几乎不发光、且没有色相」。深蓝 `(20,30,60)` gamma 后最大通道只有 4，
  但 `s≈0.67` → **不算黑**、保留下来靠色相保底可见，不会误杀封面里的暗彩色。
- **回填**：候选池只取这张封面真实采到的非黑颜色（按原顺序去重），黑位按位置轮转
  `pool[序号 % len(pool)]` 取色 —— 确定性、不随机、切歌不闪，也不会让连成一片的黑区
  全变成同一个颜色。上例的 2 个黑位会变成池里前两个不同色（蓝 / 红，或任意两个彩色）。
  **代价**：黑区的「灯带左右 ↔ 封面左右」空间对应被打破，这是「不许有黑灯」的必然取舍。
- **全黑封面**：候选池为空时，取最亮那颗、保留色相把明度提到 `0.35`，8 颗统一用它；
  纯 `#000` 图退化成中性灰。仍是封面来的颜色，只是提亮，不会凭空造彩色。
- 只改发灯的 8 颗基色：面板「配色」行、`self.color`、`--cover-layout` 语义都不动 ——
  面板如实显示封面确实有黑，便于诊断「采样有黑、灯没发黑」。

这和色相保底 `with_glow()` 是两层：`with_glow` 在**输出层**救「有颜色但被 `int` 截断成 0」
的灯珠；去黑回填在**取色层**解决「这颗根本没有颜色」。回填后黑灯变彩色，保底自然不再触发。

## 终端面板

默认会在终端画一块仪表盘（ANSI 真彩色，2Hz 刷新 —— 面板与渲染帧率解耦，跟 100Hz 会太闪）：

```
┌──────────────────────────────────────────────────────┐
│ ● 音乐呼吸                                  50.0 fps │
├──────────────────────────────────────────────────────┤
│ ♪   海鸥  —  逃跑计划                                │
│ ▶  ████████████░░░░░░░░░░░░░░  02:15 / 04:32         │
├──────────────────────────────────────────────────────┤
│ 配色 ▛▛▛▛▛▛▜▜▜▟  4 色                                │
│ 输出 4.5/8 颗  亮度 27%  峰值 0.489                    │
│ 灯珠 ▇▇▇▇▇▇▇▇                                        │
│ 板载  灭 · 待机静默                                 │
└──────────────────────────────────────────────────────┘
```

底部几行是实时预览：`配色` 按权重显示封面的取色结果，`输出` 显示当前输出峰值换算出的
颗数 / 亮度 / 原始峰值，`灯珠` 显示此刻真正发给单片机的 8 颗灯颜色
（声音驱动的明暗与颗数变化能直接从这两行看出来），`板载` 显示 GPIO2 那颗灯此刻在干什么 ——
平时是「灭 · 待机静默」或「常亮 · 麦克风在用」，事件发生后会把
「闪 1 · 封面就绪」「闪 2 · 切歌」「闪 3 · 状态切换」保留 1.5 秒。
`--no-status-led` 时这行不显示。 切到 `mic` 态时，曲目区会换成一行麦克风状态：
待机时标题变成「待机全灭」、状态行显示「待机 · 全静默（灯带与板载都灭）」；
录音中显示「电平 5.3/8 · 亮度 43% · 峰值 0.052」，再加正在使用的应用名。

几个实现细节：Windows 控制台默认关闭虚拟终端，不显式打开的话色块会变成一串乱码转义符，所以启动时会调 `SetConsoleMode` 打开 `ENABLE_VIRTUAL_TERMINAL_PROCESSING`；拿不到 ANSI 时自动降级成单行输出，不会画出一堆乱码。中文按 2 列宽计算，保证边框对齐。

**进度条只在播放器真的上报了时间轴时才画**。网易云桌面端不上报（`position` 和 `end_time` 全是 0），这时只显示"播放中/已暂停"，不画进度条也不显示时间——硬凑一个 `00:00 (时长未知)` 纯属噪音。浏览器播视频一般会正常上报。

## 串口协议

固件和电脑端靠这个通信，改固件时需要同步改 `led_host.py` 里的常量。

**帧格式**：`A5 5A | CMD | LEN | PAYLOAD[LEN] | CRC8`

CRC8 覆盖 CMD+LEN+PAYLOAD，多项式 0x07，初值 0x00。波特率 115200。

| CMD | 名称 | Payload | 用途 |
|---|---|---|---|
| `0x01` | SET_ALL | 24B，RGB×8 | 一次设定全部灯珠（主力命令，100Hz） |
| `0x03` | BRIGHTNESS | 1B | 全局亮度 |
| `0x04` | HEARTBEAT | 0B | 保活 |
| `0x06` | OFF | 0B | 立即熄灭（灯带 + 板载 LED，并标记「主机主动退出」） |
| `0x07` | STATUS_LED | 1B | 板载 LED 常驻灯态：`0`=灭 `1`=常亮 `2`=慢闪（本项目只用 0/1）。带缓存，只在变化时发 |
| `0x08` | STATUS_PULSE | 1B | 板载 LED 短闪 N 下后自动熄灭（切歌 `2` / 状态切换 `3`）。**永不缓存** |
| `0x10` | HANDSHAKE | 0B | 回应固件版本号，电脑端启动时用它确认对面是本项目的固件 |

固件侧三条保护：

- **半帧 100ms 超时重置** — 一串干扰字节不会把解析状态机卡死
- **CRC 校验** — 坏帧直接丢弃
- **心跳 3 秒超时渐灭** — 电脑关机/休眠/进程退出时不会僵在最后一帧

渲染帧率是 **100Hz**：输出峰值由 Windows 音频引擎按约 10ms 的设备周期更新，
50Hz 采样容易重复读同一值或漏掉瞬态，100Hz 才贴得上；麦克风电平表也一并受益。
串口每帧 29 字节 × 100 = **2900 B/s**，占 115200 的 **25.2%**；
ESP8266 刷 8 颗 WS2812 只要 0.24ms，10ms 间隔绰绰有余，固件 3 秒心跳超时也不受影响。
一帧纯计算约 59µs（含 41µs 的峰值读取），100Hz 下占 CPU 约 0.6%，远不是瓶颈。
所有平滑时间常数都按秒定义或由帧间隔推导，帧率翻倍不改变平滑手感；
注册表占用扫描仍是独立的 20Hz（`MIC_POLL_INTERVAL`），面板仍是 2Hz。

## 常见问题

**设备管理器里驱动版本变回 3.9，灯不工作了**
Windows 更新会把 CH340 驱动顶到 3.9（有 bug）。跑上一级目录的 `ch340-fix.bat`（管理员），它会删掉驱动存储里的 3.9 包并禁止 WU 再推送。详见 `状态指示灯-方案设计.md`。

**pip 装包报 `from versions: none`**
换阿里源，见上面"装依赖"。

**偶尔出现第二颗亮、第一颗不亮**（已修）
不是控制层没跟上，也不是亮度设太低：封面左列若是深色，过 gamma 后只剩
`(0,1,4)` 这类值，再乘低亮度系数会被 `int` 截断成 `(0,0,0)` ——
逻辑上点亮了、肉眼却看不见；旁边亮色那颗仍可见，就成了「跳过第一颗」。
实测即使把亮度拉到最高 0.37，深蓝那颗也只有 `(0,0,1)`。
现在 `with_glow()` 给极暗灯珠按自身色相补一丝微光（保底强度随亮度缩放，
静音侧约 1/255、满档 3/255），亮几颗就看得见几颗。

**放歌时颜色几乎都是很亮的白色**（已修）
早期放歌帧走 `raw=True` 直出，却把声音亮度直接乘在**感知 RGB** 的封面色上 ——
绕过 gamma 后亮通道被拉满、暗通道也被一起抬起，看起来就是过曝泛白。
现在先把封面色逐通道过 gamma 再乘亮度：最亮白色封面回到约 **94/255**
（与旧封面呼吸的 `gamma(255×0.70)=93` 一致），橙色封面 `(255,100,50)`
得到 `(94,7,1)`，旧灯效最亮是 `(93,7,1)`。
白/浅色封面的灯本来就会偏白，那是封面本身的颜色，不是故障。

**音乐声音很小 / 根本没声音时，第一颗却还是亮着**（已修四次）
- **颗数**：早期放歌模式照搬了麦克风 VU 的门限 `MIC_SOUND_GATE = 0.02`，
  数字输出静音就是 0、小音量 peak 轻易低于 0.02，颗数直接算成 0。
  现在放歌**不套这个门限**（颗数 `1 + lv×7`，至少 1 颗）。
- **亮度**：一度加过 `RENDER_MIN_LEVEL = 0.05` 保底，第一颗一上来就固定 5%
  （约 13/255），低音量段形成又亮又不变的平台，已删。
  现在 `render_brightness()` 是 `RENDER_BRIGHT_FLOOR(0.01)` 到
  `RENDER_BRIGHT_MAX(0.37)` 的**线性插值**：1% 起步、全程连续，没有平台。
- **真静音门限**：数字输出静音时端点峰值精确为 0，所以
  `peak < RENDER_SILENCE_GATE = 0.005` 时**一颗都不亮**；刚过门限才从 1% 起步。
  「完全没声音全灭」和「极小声留一丝微光」并不矛盾。
- **色相保底的平台**：为修「第二颗亮、第一颗灭」加的固定 3/255 保底，
  在深色封面上会覆盖整个音量范围（`(0,1,4)` 乘满档 0.37 也只有 1），
  让第一颗从静音到最大声恒定不变。现在保底强度随亮度缩放，平台消失。
- 麦克风 VU 的 0.02 门限没动，之前「没声音不亮」的行为保持不变。
- **另一个常见误判**：`GetPeakValue` 读的是默认输出设备的**混音数字电平**，
  不等于你耳朵听到的响度：其它应用声音、系统提示音都算，数字音乐做过响度
  归一化，安静段落的瞬时峰值也不低，且常不随播放器/系统音量滑块等比变化。
  把系统音量静音后跑 `--diagnose` 看「当前 peak」是否仍非零，就能确认这一点。

**放歌时只亮两三颗 / 一直不满 8 颗**
默认 `--render-full-peak 1.00` 很保守：本机实测普通音量播放的输出峰值平均约 0.22、
最大约 0.49，映射后落在 2~4 颗。校准：播放常听的歌，跑
`python led_host.py --render-calibrate`，按它给的 `--render-full-peak`（本机约 0.48）
调小就更活跃；反过来总是 8 颗就调大（允许略大于 1，例如 1.2 可压住音乐瞬态峰值，
但第 8 颗会变难出现）。改完重跑 `--autostart install` 固化。
若校准命令显示「输出端点峰值接口不可用」，程序已自动降级回整条封面呼吸，
这时 `--breathe-period` / `--breathe-depth` 才重新起作用。

**灯一直不亮**
先 `--diagnose` 看有没有媒体会话。媒体源需要 WinRT 绑定 + Pillow，缺了程序会明确提示装什么；
装不齐时程序照常运行，只是灯保持熄灭。**麦克风没在使用时灯带和板载 LED 本来都是灭的**，
完全静默，别误以为灯坏了。

**麦克风灯不跳档 / 一直全灭**
跑 `python led_host.py --diagnose` 看「麦克风体检」：会打印当前判定、正在使用的应用、
最近 8 条访问记录、**设备峰值**、固定量程与声音门限，以及 8 档「颗数 / 亮度」预览。
- 「占用检测不可用」= 注册表读不到（非 Windows，或系统隐私设置把麦克风访问整个关掉了）。
- 「电平接口不可用」= COM 峰值表拿不到，会降级成二值指示：在用就按 80% 亮度亮满 8 颗。
- 「在用」但灯全灭 = 去抖没走完（约 0.25 秒），或者真的没声音（低于声音门限）；
  这是特意做的：没声音时一颗都不亮。开着系统录音机说话测最直观。

**普通音量 / 贴嘴说话就 8 颗全亮**
不是麦克风动态范围低。旧版有两道提前封顶：满档峰值只有 0.35（WASAPI 是 0~1），
且 lv≥0.70 就亮满 8 颗 —— 合起来 peak≈0.25 就到顶。现在量程吃满 1.00、
且 lv=1.0 才满 8 颗。校准：先让一个应用占着麦克风，再跑
`python led_host.py --mic-calibrate`，用正常音量说 5 秒，
脚本打印**最大 / 平均 peak、顶到 1.0 的帧占比**和建议的 `--mic-full-peak`。

**`--mic-calibrate` 显示 peak = 1.0000（削波）**
本机实测就是这个结果：最大 1.0000，麦克风信号已经被推到数字满幅。
此时 `lv` 恒等于 1，任何声音都是 8 颗 / 80%，**改软件参数解决不了**：
`--mic-full-peak` 已经是物理上限 1.00，调小只会更早满档。脚本会识别削波并给出指引，
按这三步从信号源头降增益，然后重测：
1. 控制面板 → 声音 → 录制 → 麦克风 → 级别：把「麦克风」滑块调低，
   「麦克风加强 / Microphone Boost」设 0dB 或关掉（+20dB 最容易打满）。
2. 关掉录音 / 会议 / 语音软件里的「自动增益控制 AGC / 自动调整音量」——
   AGC 会自动把信号推到顶。
3. 麦克风离嘴 15~20cm，别贴着说。

重测目标：正常说话 peak 落在 **0.3~0.6**、削波占比接近 0%（对应 3~5 颗 / 20~45%），
大声喊才接近 0.9~1.0 → 8 颗。测好后若要改 `--mic-full-peak`，重跑
`--autostart install` 固化。

**灯一直是 8 颗不回落**
多半是某个应用崩溃/被强杀，没来得及写 `LastUsedTimeStop`，留下了 `Start > Stop`
的僵尸记录。脚本会忽略超过 6 小时的 `Start`，所以最多 6 小时后自动恢复；
想立刻清掉可以删 `ConsentStore\microphone` 下对应应用的 `LastUsedTimeStart`。

**板载 LED 一直在温柔呼吸**
那是「主机失联」提示，不是故障：后台服务没在跑（忘了装自启 / 被 `--autostart stop` 停了）、
USB 线断了、或者串口号不对。看 `host/logs/led_host.log` 能一眼分出是哪种。
主机正常推流后呼吸立刻停；Ctrl+C 退出会先发 `OFF`，所以手动关掉是安静的，不会呼吸。

**板载 LED 一直常亮 / 一直是灭的是什么意思**
常亮 = 有程序在用麦克风；灭 = 待机静默（灯带也全灭）。两者都是常驻状态，不是故障；
待机不再闪烁。另外闪 2 下 = 切歌了，闪 3 下 = 灯效状态切换（放歌 ↔ 麦克风态 ↔ 熄灭），
那是事件脉冲，闪完会回到常驻状态。整块关掉用 `--no-status-led`。

**打不开串口**
Arduino IDE 的串口监视器、PlatformIO Monitor 会独占 COM 口，烧录或运行时必须关掉。也可能串口号不对，用 `--list-ports` 确认。

**睡一觉起来灯不亮了 / 串口断了**
已内置**自动重连**：断链后按 1→2→4→8…（上限 30 秒）指数退避重试，端口号变了也能按 CH340 描述重新找到；连上后自动重新握手并恢复亮度。日志会打印 `[!] 串口断开` 以及每次重试结果。若一直连不上（比如 USB 被拔掉），Ctrl+C 退出即可。

**媒体源显示"没有任何会话"**
确认播放器已注册到系统媒体接口：`python led_host.py --diagnose`。网易云的 AppUserModelID 是 `cloudmusic.exe`。

## 数据源实现说明

两个源。**媒体**（SMTC，系统媒体传输控制）优先：拿缩略图 → 九宫格配色 → 铺到灯带。
遍历**所有**会话而不只看 `get_current_session()`（网易云常不是系统认定的当前会话）。只在换歌时解码封面。

**封面配色算法**：切成 3×3 九宫格（中心块权重 1.8、边 1.1、四角 0.8，因为主体通常在中间）→ 每格各自量化取色 → 按 **HSV 分桶**合并同色系（色相 30° 一档）→ 取前 4 色归一化权重。

打分是三个维度：`像素占比 × 位置权重 × (0.65 + 0.35×饱和度) × (0.40 + 0.60×明度)`。

- **饱和度只做轻微加权**（0.65~1.0）。早期用 `(0.35 + 0.65×s)` 惩罚太重，白色(s=0)的权重只剩彩色的 35%，大块白底反而被小面积彩色抢走。
- **明度**让暗部权重降低但不清零，黑色会进入配色候选；但发灯前会被「去黑回填」
  换成同一张封面里的其它颜色（见「封面取色方式」），所以灯带上不会出现黑灯。

最终颜色的处理有两条铁律：

1. **绝不给饱和度设下限。** 一旦设了（试过 `sat_min=0.40`），白色(s=0)和黑白灰会被硬染成彩色——而灰度的色相恰好是 0（红），表现为"大块白色变成红橙"。现在 `sat_min=0`，黑白封面就是纯灰阶，靠明度出层次。
2. **明度用 gamma 提亮，不用 min-max 归一化。** 后者会把"最暗的那色"强行拉到下限，于是白底(v=1.0)上的一块亮红(v=0.90)会被当成"最暗"压成暗红(实测变成 RGB(76,17,12))。改成 `v^0.70` 后只抬暗部、几乎不动亮部，亮红保持 RGB(237,52,36)。整体偏暗的封面（最亮色仍 <0.75）再统一增益，避免灯几乎不亮。

四个踩过的坑：
- 合并必须用 HSV 不能用 RGB：按 RGB 量化会把同色系的深浅变化当成不同颜色，配出来几色几乎没差别
- 提亮只能设下限不能设统一值：`val_min=0.75` 会把所有颜色压成同一亮度，层次全丢
- 排除阈值不能太高：`v < 0.05` 会把「大片黑 + 小块亮」里的黑整个丢掉，现在改成 0.02
- 上面两条铁律：饱和度下限 = 白变红橙；min-max 归一化 = 亮色被压暗

**切歌响应**：注册 SMTC 的 `media_properties_changed` / `playback_info_changed` 事件，切歌时回调立刻触发采样；另有 0.5 秒轮询兜底（事件万一不派发也不会卡住）。媒体线程跑的是**常驻 asyncio 事件循环**而不是反复 `asyncio.run()`——否则事件回调根本没有机会被派发。

**切歌后颜色不更新的坑（已修）**：SMTC 的标题和封面**不是同时更新**的。原来用"标题变了才解码"做缓存，结果切歌瞬间读到的还是上一首的封面，标题却已经是新的 —— 颜色就永远锁死在旧封面上。现在改成比对**封面字节的 MD5**：切歌后置 pending，最多 5 秒内反复取封面，
直到哈希真的变化才更新取色；**这一刻会让板载 LED 闪 1 下**，标记「封面已就绪」，
免得你不知道网易云那种延迟什么时候结束（详见「板载 LED」一节）。

三个已知坑（代码里已处理）：

- `read_async()` 必须 await，否则第二次调用拿到空 buffer
- 新版 PyWinRT 里 `DataReader.read_bytes(n)` 会报 `TypeError`，正确写法是直接 `bytes(buffer)`
- 提亮只能设下限不能设统一值：`val_min=0.75` 会把所有颜色压成同一个亮度，配色层次全丢，现在用 0.60 且只补下限

## 网易云能拿到哪些 SMTC 信息

实测结果（2026-10，网易云 PC 客户端 `cloudmusic.exe`）：

**能拿到**

| 字段 | 值 |
|---|---|
| `source_app_user_model_id` | `cloudmusic.exe`（用来做 `--app-filter`） |
| `title` | 歌名 ✓ |
| `artist` | 艺术家 ✓ |
| `thumbnail` | 封面图 ✓（本项目就靠它） |
| `playback_status` | 播放状态：Playing / Paused / Stopped 等 ✓ |
| Controls | `is_pause_enabled`、`is_next_enabled`、`is_previous_enabled` 均为 True |

**拿不到**（返回空、0 或 None）

| 字段 | 实际返回 |
|---|---|
| `album_title` / `album_artist` / `subtitle` | 空字符串 |
| `genres` / `track_number` / `album_track_count` | 空 / 0 |
| `playback_rate` / `is_shuffle_active` / `auto_repeat_mode` | None |
| 时间轴 `position` / `end_time` / `start_time` | 全是 0 —— **没有时长和进度** |
| `try_seek_async` | 方法不存在，无法拖动进度 |

**可以反向控制**（方法都存在，Controls 也标记为允许）：`try_pause_async`、`try_skip_next_async`、`try_skip_previous_async`、`try_toggle_play_pause_async`。也就是说理论上能让灯去切歌，不过目前没这个需求。
