# 音乐封面呼吸灯（WeMOS D1 mini + 8 颗 WS2812B）

把 D1 mini 变成一盏会看场合的灯，两件事，按优先级：

1. **有音乐在播** —— 认出电脑上正在播放的音乐，把专辑封面解成配色铺到 8 颗灯珠上，
   整条灯带跟着一个缓慢的呼吸节奏明暗起伏。
2. **没在播音乐** —— 麦克风没被占用时**灯带全灭**，只留板载 LED **1Hz 亮灭**表示待机；
   麦克风一被占用，板载 LED **常亮**，灯带变成一条 **50Hz 的电平表**：
   音量同时决定 **亮几颗**（1~8，从离板子最近的那颗往最远的长）、
   **什么颜色**（绿 → 黄 → 橙 → 红）和 **多亮**（最终占空比 1% → 95%）；
   **没声音或声音极低时一颗都不亮**。

**封面呼吸**受 `--max-level` 的 70% 上限限制；**电平表是例外**，
它按自己的亮度曲线以最终 PWM 占空比直出（否则 1% / 10% 过 gamma 会全黑）。

**板载 LED（GPIO2 / D4）兼两职**：常驻状态（未占用 1Hz 闪 / 占用常亮）+ 事件脉冲
（切歌闪 2 下、状态切换闪 3 下）。麦克风关闭就恢复 1Hz 闪（详见「板载 LED」一节）。

**设计原则：智能全在电脑端，ESP8266 只当哑终端。** 改配色、调呼吸节奏、换取色方式都不用重新烧录。
唯一例外是板载 LED 的失联提示 —— 那时候串口已经断了，电脑根本发不出命令，只能由固件自己判断。

> 本项目早期做过节拍闪烁（BPM 预测 + 起音跟随）、人工打拍子、GPU 占用条、CPU 进度条、
> 麦克风「整条绿/整条橙」的二值指示，以及「没播音乐时跟屏幕画面走」的抓屏氛围光，
> 这些都已**全部移除**，代码也删干净了。`host/` 下只有 `led_host.py` 一个脚本
> （采集、配色、麦克风占用/电平、面板、串口输出都合并在里面）。
>
> 抓屏氛围光是最后一个被砍的，原因是它两头不讨好：独占全屏的游戏（地平线 5、赛博朋克 2077
> 默认都是）画面不进桌面合成器，GDI 抓到的是纯黑，灯反而灭掉；而 GDI 从桌面 DC 回读
> 2560×1440 一次要 16ms，5Hz 抓屏就要吃掉单核 8%。麦克风检测只读注册表 + 一个系统峰值接口，
> 单次不到 0.1ms，跟画面怎么输出毫无关系。

## 硬件

| 项 | 值 |
|---|---|
| 数据脚 | **GPIO4（D2）** |
| 灯珠 | 8 颗 WS2812B |
| 板载 LED | 开发板自带的蓝色 LED，**GPIO2（D4）**，低电平点亮，用作麦克风状态指示 + 事件提示 |

三个必须注意的点：

1. **别用 GPIO0。** 它是 ESP8266 的 strapping 引脚，上电被拉低会让芯片进 UART 下载模式、固件根本不跑（症状：插上灯不亮，重新烧录又能亮）。灯带掉电/上电时序错开时，DIN 的 ESD 二极管会倒灌把它拉低。GPIO4 没有这个问题。
2. **电平匹配。** ESP8266 是 3.3V，WS2812B 在 5V 供电下要求高电平 ≥3.5V，3.3V 直驱属于擦边球——短距离能亮，但换灯带或温度升高后会首灯错色。正解是 74AHCT125/74HCT245 做电平转换；省钱解是给灯带串一只 1N4001 把 5V 降到约 4.3V，阈值随之降到 3.0V。
3. **供电。** 8 颗满亮约 480mA，加板子自身已逼近 USB 500mA 上限，会触发过流重启（表现是灯闪一下全灭）。所以封面呼吸默认压在 `--max-level 0.70`（电平表用的是饱和单色，见「亮度」一节）；灯带最好单独 5V 供电、与板子共地不共 5V。灯带 VDD/GND 并 100~470µF 电容，DIN 串 330Ω 电阻。

## 快速开始

### 1. 装依赖

```
cd host
pip install -i https://mirrors.aliyun.com/pypi/simple -r requirements.txt
```

**别用清华源**：清华源的 `winrt-*` 只有 `2.0.0b1` 预发布源码包，pip 默认跳过预发布，会报 `Could not find a version (from versions: none)`。

**别装 `winsdk`**：那个包已废弃，最后版只支持到 Python 3.12。

### 2. 烧固件

Arduino IDE 正常烧 `ESP-WS2812.ino`，板子选 `LOLIN(WEMOS) D1 R2 & mini`。烧完板载蓝灯连眨 3 下表示固件跑起来了。

命令行编译（可选）：

```
"C:\Users\yoea\AppData\Local\Programs\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe" compile --config-file "C:\Users\yoea\.arduinoIDE\arduino-cli.yaml" --fqbn esp8266:esp8266:d1_mini "D:\Develope\esp8266\3.WeMOS D1 mini\ESP-WS2812"
```

必须带 `--config-file`，否则找不到库（sketchbook 在 `D:\Develope\Arduino`，不是默认的 Documents\Arduino）。

### 3. 跑

```
python led_host.py                       # 默认：跟随媒体封面呼吸
python led_host.py --list-ports          # 确认串口号
python led_host.py --demo                # 灯带自检
python led_host.py --diagnose            # 体检媒体源 / 麦克风
python led_host.py --autostart install   # 装成开机自启的后台常驻（见下节）
```

## 开机自启 / 后台常驻

```
python led_host.py --autostart install   # 装：以后每次登录 Windows 自动在后台跑，没有窗口
python led_host.py --autostart status    # 看：装没装、在不在跑、上次什么时候跑的、日志在哪
python led_host.py --autostart start     # 立刻启动一次（不用等下次登录）
python led_host.py --autostart stop      # 临时停掉（灯熄灭；不卸，下次登录还会起来）
python led_host.py --autostart remove    # 彻底卸掉自启
```

第一次 `install` 会弹一次 UAC —— 注册计划任务需要管理员。装好后在
**任务计划程序库**里有一个叫 **`ESP-WS2812 音乐封面呼吸灯`** 的任务，点开它的「描述」
写着它是干嘛的、日志在哪、怎么停怎么卸，忘了的时候看那一栏就行。

自带三件事：登录后 **20 秒**才启动（等 USB 枚举完）、串口没就绪会**最多等 30 秒**、
进程意外退出会**自动重启 3 次**（每次间隔 1 分钟）。

### 为什么是任务计划程序，不是 Windows 服务

服务一律跑在 **Session 0**，跟登录进来的桌面会话是隔离的。本程序靠 SMTC
（系统媒体传输控制）读「正在放什么歌」，而 SMTC 是按用户会话枚举的 —— 在 Session 0 里
拿到的会话列表恒为空，灯会永远不亮，等于白装。

任务计划程序的进程跑在用户会话里，媒体源正常，同时也有服务的三样好处：
开机自启、无窗口、失败自动重启。所以它是这里的正解。

### 后台运行时怎么排查

界面全部关闭，输出只进 `host/logs/led_host.log`（超过 1MB 自动滚成 `.old`）：

- 每次启动写一行 `--- 后台启动 ---` 加完整命令行；
- 切歌写一行 `[media] 歌名 — 歌手`，停了写 `[media] （没在播放）`；
- 串口断开/重连也都在里面。

灯不亮时先看这个日志，多半一眼能看出来是串口没连上还是媒体源没读到。

### 装不上时的降级方案

UAC 被取消、或者机器上根本没管理员权限时，可以用不需要管理员的「启动文件夹」方案：

```
python led_host.py --autostart install --method startup
```

它往「启动」文件夹放一个 `ESP-WS2812 音乐封面呼吸灯.vbs`（UTF-16，开头有中文注释说明
用途和关闭方法），效果一样，只是少了「崩溃自动重启」。两种方式互斥，装了前者会自动清掉后者。

## 灯效一：封面配色 + 呼吸

| 条件 | 状态 | 表现 |
|---|---|---|
| 有音乐在播 | `media` | 8 颗铺封面配色，整条同步呼吸 |
| 停了 1.5 秒以上 | 交给麦克风电平表 | 见下 |

切歌/暂停会有零点几秒没有 `Playing` 的空档，所以切走留了 **1.5 秒缓冲**（`MEDIA_FALLBACK_DELAY`），不然每次切歌灯都要闪一下。

## 灯效二：麦克风电平表（没播音乐时）

| 麦克风状态 | 亮几颗 | 颜色 | 亮度（最终 PWM 占空比） |
|---|---|---|---|
| 没被任何程序占用 | **0 颗（全灭）** | —— | 改由板载 LED 以 1Hz 亮灭 |
| 正在用，没声音 / 声音极低 | **0 颗（全灭）** | —— | 声音门限以下不亮 |
| 刚有声音 | **1 颗** | 绿 | **1%** |
| 声音稍微起来 | 仍是 **1 颗** | 绿 | **10%** |
| 声音中等 | **3~6 颗** | 绿 → 黄 → 橙 | **26% ~ 43%** |
| 8 颗刚全亮 | **8 颗** | 末端红 | **60%** |
| 再往上加音量 | 仍是 **8 颗** | 不变 | **77% → 95%** |

**颜色按亮起顺序分段**：第 1 颗绿(120°)，线性过渡到黄(60°)、橙(30°)，第 8 颗红(0°)。
**点亮方向从最近端往最远端**：WS2812 帧里 index 0 是数据线进来的第一颗（离板子最近），
index 7 是灯带末端（最远），所以默认按 `0 → 1 → … → 7` 长。
`--mic-reverse` 翻回 `7 → … → 0`。

### 音量怎么同时控制三件事

`MicLevel` 把设备峰值归一化成 `lv`（0~1），再走两条独立曲线：

| lv | 0 | 0.02 | 0.12 | 0.30 | 0.50 | 0.70 | 1.00 |
|---|---|---|---|---|---|---|---|
| 颗数（`mic_led_count`） | 0 | 1.0 | 1.0 | 3.2 | 5.6 | 8.0 | 8.0 |
| 亮度（`mic_brightness`） | 0% | 1% | 10% | 26% | 43% | 60% | 95% |

两处关键：
- **声音门限 `MIC_SOUND_GATE = 0.02`**：麦克风虽然被激活，但没声音 / 声音极低时
  `mic_led_count()` 直接返回 0，8 颗全灭；只有真检测到声音才亮起来。
- **不要把 1.0 直接当「8 颗满亮」**：`0 → 0.70` 用来长颗数（`0.12` 之前只亮 1 颗，
  先让亮度从 1% 抬到 10%），`0.70 → 1.00` 颗数固定 8，专门留给亮度继续往上走。
  这样满 8 颗之后，声音再大仍有可辨识的变化，不会出现「到顶了就没反应」。

亮度按 `MIC_BRIGHT_STOPS` 分段线性插值，单调递增；最后一颗按小数渐入，不是硬跳档。
不是频谱、也不是硬跳的档位：50Hz 下看起来是连续的 VU 条。
**只有电平表**的颜色平滑单独用 **0.035s**（其余态 0.15s），否则低通会把波形削平；
待机用 0.15s 还能让「录音结束 -> 全灭」的收尾更柔和。

### 「谁在用」和「声音多大」是两件事

**谁在用** —— 读 Windows 隐私同意记录：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\
    ConsentStore\microphone
    ├─ <打包应用包名>\LastUsedTimeStart / LastUsedTimeStop
    └─ NonPackaged\<Win32 路径，反斜杠写成 #>\...
```

每个真的打开过麦克风捕获流的进程都有一对 FILETIME（1601 起算的 100ns 计数），
**`Start > Stop` 就是「这个进程正在录音」**。任务栏那个「麦克风正在使用」小图标
用的也是这份数据。只用标准库 `winreg`，一次扫几十个子键不到 1ms。

**声音多大** —— 读 WASAPI 的 `IAudioMeterInformation::GetPeakValue`，也就是
Windows 音量条同款的**设备级峰值**（0~1）。它**不打开捕获流**，这一点是关键：
如果为了拿音量自己起一路录音（ffmpeg / pyaudio 都行），那个进程会把自己写进
ConsentStore，于是「麦克风没在使用」永远不成立，待机（全灭 + 板载闪）就再也回不去了。
峰值表只读设备，注册表判定保持干净。用 `ctypes` 手写 COM vtable 调用，
**零第三方依赖**（不需要 pycaw / comtypes / numpy / pyserial 之外的任何东西）。

> 接口 IID 是 `C02216F6-8C67-4B5B-9D00-D008E73E0064`。
> 网上常见的 `…D01E1FE83D21C` 是错的，`Activate` 会直接回 `E_NOINTERFACE`。

**实测**（本机 Realtek 麦克风，ffmpeg 模拟他人录音 + 播放 440Hz 测试音）：

| 场景 | 设备峰值 |
|---|---|
| 没有任何程序捕获 | **恒 0.0000**，播放声音也是 0（设备没上电） |
| 有程序捕获、安静 | 0.0066 ~ 0.0105（底噪） |
| 有程序捕获、出声 | 0.104 ~ 0.108（**10 倍**），响应 <0.25s |
| 6 秒音量线性渐大 | 0.009 → 0.083 单调递增，归一化后 1~8 档全覆盖且分布均匀 |

单次 `GetPeakValue` 只要 **21.5 微秒**，50Hz 采样占 CPU 约 0.1%。
额外好处：peak 恒 0 可以当「没人在用」的交叉验证，还能识破注册表里的僵尸记录。

### 电平归一化：固定量程，别让满档跟着声音跑

早期这里用过「滚动峰值参考」，结果是个真 bug：`peak` 一超过参考值就立刻把参考
抬到 `peak`，于是 `target = (peak-floor)/(ref-floor) = 1.0` —— **任何正常说话都会
直接算成满档 8 颗**，只有压低声音、等参考衰减下来才会回到 1~2 颗。

现在量程固定不动：

- `lv = clamp((peak - 0.006) / (MIC_FULL_PEAK - 0.006), 0, 1)`，
  `MIC_FULL_PEAK` 默认 **0.35**，可用 `--mic-full-peak` 改。
- 实测映射：peak 0.10 → lv 0.273 → **2.8 颗 / 23%**；
  peak 0.02 → lv 0.041 → **1 颗 / 3%**；peak 0.35 → **8 颗 / 95%**。
- 量程不会被声音撑大，响度关系稳定；电平本身再做 0.035s 快平滑，跟手但不抖。
- 麦克风增益因机器而异：**用普通音量说话时跑一次 `--diagnose`，看「当前设备峰值」**。
  若还是动不动满档就把 `--mic-full-peak` 调大（如 0.6），几乎不亮就调小（如 0.15）。
  `--autostart install` 会把这个参数固化进自启任务。

### 两个必须处理的坑

- **输入法 / 语音助手的短脉冲**：本机记录里 DoubaoIME、千问输入法、微信、Typeless
  都开过麦克风，最短的一次只有 **75ms**。若直接按 `Start > Stop` 亮灯，会莫名其妙跳档。
  所以加了双向去抖：连续在用 **0.2s** 就认（注册表每 **0.05s** 扫一次，
  最坏约 **0.25s** 出灯；0.2s 仍大于那 75ms 的短脉冲，不会误触发），
  连续空闲仍要 **1.5s** 才放开，免得说话中的停顿让灯来回跳。
- **进程崩溃残留**：被强杀的进程不会写 `Stop`，`Start > Stop` 会永远成立。
  所以 **超过 6 小时**的 `Start` 一律当成僵尸记录忽略；peak 恒 0 也能辅助识别。

`python led_host.py --diagnose` 会列出当前判定、正在使用的应用、最近 8 条访问记录、
设备峰值、固定量程与声音门限，以及 8 档「颗数 / 亮度」电平预览。
接好麦克风后跑一次就能确认检测正不正常。

> 早期这里先是 **CPU 占用进度条**，后来改成「整条绿 / 整条橙」的二值指示，
> 都已按需求完整移除，相关代码也删干净了。

## 板载 LED：麦克风状态 + 事件脉冲 + 失联呼吸（GPIO2 / D4）

D4 上这颗开发板自带的蓝色 LED（低电平点亮）。现在它**常驻表达麦克风有没有被占用**，
灯带待机全灭时，它就是唯一的状态指示：

| 板载 LED | 含义 | 谁决定 |
|---|---|---|
| **1Hz 亮灭**（500ms 亮 / 500ms 灭） | **麦克风没被占用**：待机，灯带全灭 | 电脑端 |
| **常亮** | **麦克风正在被占用** | 电脑端 |
| **闪 2 下**（亮 90ms / 灭 130ms） | **切歌了**：曲目标题或歌手变了 | 电脑端 |
| **闪 3 下** | **灯效状态切换**：放歌 ↔ 麦克风态 ↔ 熄灭 | 电脑端 |
| **温柔呼吸**（PWM 渐亮渐暗，2.6s 一个来回） | **主机失联**：USB 线断了 / 电脑关机 / 后台服务崩了 | 固件自己判断 |

麦克风一关闭就恢复 1Hz 闪，不用重启服务。状态只看「有没有程序在用麦克风」，
与放不放歌无关 —— 所以放歌时麦克风没占用，板载灯也是 1Hz 闪。
要整块关掉（连事件脉冲一起）用 `--no-status-led`。

### 实现：为什么 1Hz 由 host 发

固件 `0x07` 本来就支持 `2` = 慢闪，但常量是 `BLINK_NORMAL_MS = 1000`
（1s 亮 / 1s 灭 = **0.5Hz**），达不到要求的 1Hz。为了不重烧固件，
改由 host 每半秒在 `0`(灭) / `1`(常亮) 之间切一次 `set_status_led()`；
它自带缓存，只在翻转时发一条，串口每秒多 2 帧（50Hz 主流量前可忽略）。
事件脉冲走 `0x08`：固件里 pulse 优先于常驻灯态，闪完自动回到常亮或闪烁，不打架。

状态切换的优先级高于切歌 —— 两件事同时发生（比如待机时直接点了首歌），
只闪 3 下，不叠加成 5 下；连续切歌有 0.8 秒冷却。
「待机 ↔ 录音电平表」只是 `mic` 态内部换灯效，`state` 没变，不闪事件脉冲
（常驻状态自己会从 1Hz 闪变成常亮）。**电平档位变化不发脉冲**：
50Hz 下一秒钟能变十几档，再让板载灯跟着闪就变成频闪灯。

### 失联为什么是呼吸

失联时灯带已经熄了（正常待机也是全灭），板载灯要是也沉默，
你就分不清「正常待机」和「出事了」—— 正常待机至少还有 1Hz 闪。
用呼吸而不是快闪是刻意的：它表示「我在，等你回来」，而不是「坏了，快来看」——
电脑关机本来就常态操作，没必要报警。峰值亮度也只到 55%，不刺眼。

判断逻辑是「超过 3 秒没收到任何一帧，**而且**主机最后一条命令不是 `OFF`」。所以：

- Ctrl+C 正常退出（先发 `OFF`）→ 灯安静地灭着，不呼吸；
- 进程被强杀 / 拔线 / 关机 / 休眠 → 进入呼吸。

上电后主机一直没连上，3 秒后也会呼吸 —— 那是在说「固件在跑，但没人在推数据」，
**不是板子坏了**。

进入呼吸会等灯带渐灭走完再开始（约 3 秒），所以从拔线到看见呼吸大约 6 秒。
这个先后顺序不能反，理由见下。

### 这里为什么敢用 `analogWrite`

早先明确说过「只用 `digitalWrite` 开关、不上 `analogWrite`」，理由是 ESP8266 的 PWM
靠定时器中断实现，会打断 WS2812 的软件位翻转。这次能破例，是因为**用它的时机变了**：

呼吸只在「主机已经不发数据」的窗口里启用。这段时间里 `strip.show()` 一次都不会调用，
**没有位翻转，也就没有可被打断的时序**。

代价是必须守住两条纪律，代码注释里都标了：

1. 进入呼吸前先等灯带渐灭走完 —— 渐灭里有 `show()`，不能和 PWM 并存；
2. `handleFrame()` 第一件事就是退出 PWM —— 收到任何一帧立刻把引脚交还给 `digitalWrite`，
   否则那一帧的 `show()` 正好会被打断。

其余场景（开机自检、事件脉冲）仍然只用 `digitalWrite`。

顺带一提，GPIO2 是 ESP8266 的 strapping 引脚之一，但板载 LED 是低电平点亮 + 板上外部上拉，
**上电时是高电平（灭）**，不会把芯片拖进下载模式 —— 可以放心用。

### 相关命令

```
python led_host.py --no-status-led    # 整块关掉（GPIO2 要接别的东西时才用）
python led_host.py --demo             # 自检时依次演示「闪 2 下」「闪 3 下」
```

失联呼吸演示不到 —— 只有真拔线或杀掉进程才会出现。

面板底部有「板载」一行：平时显示「闪 1Hz · 待机」或「常亮 · 麦克风在用」，
事件发生后换成「闪 2 · 切歌」「闪 3 · 状态切换」并保留 1.5 秒（见「终端面板」一节）。

## 亮度：封面呼吸 70% 上限，电平表走自己的曲线

封面呼吸受 **70%**（`--max-level 0.70`）限制，在 **gamma 之前**乘到每颗灯上
—— gamma 是「感知亮度 → PWM」的映射，乘在前面才是真的把亮度降到 70%；
乘在后面等于把 PWM 砍掉 70%，会暗得多。
70% 感知亮度对应 PWM `gamma(178) = 93`，8 颗约 173mA，加板子约 250mA，离 USB 500mA 还有余量。

**电平表是唯一例外。** 它要表达 1% / 10% / 60% / 95% 这种**最终 PWM 占空比**
（和你最早那颗「10% 绿灯」同一口径）。如果再走一遍 `gamma(i)=255*(i/255)^2.8`，
10% 会被压到约 0.4/255、1% 直接是 0，低音量段全黑，亮度维度就废了。
所以 `mic_leds()` 直接算好最终 PWM 值，`LedStrip.set_all(..., raw=True)` 原样发出，
绕过 gamma 和 `max_level`。

95% 会不会过流？按通道数估算，VU 用的是饱和单色（绿/红一通道、黄/橙两通道），
不是白色三通道全开，8 颗约 230~300mA，仍低于「8 颗全白满亮」的约 480mA；
但它确实比原来的 70% 感知亮度亮不少。接在 USB 口上若出现过流重启，
把 `MIC_BRIGHT_STOPS` 最后一个锚点（0.95）调低即可。

`--brightness`（固件侧）默认满档，不再二次打折：**两道相乘会把 70% 压成 37%**
（`128/255 × 0.70`），灯肉眼可见地偏暗。封面呼吸调 `--max-level`，
电平表调 `MIC_BRIGHT_STOPS`，各管各的。

### 呼吸怎么算

亮度在一个周期内按余弦平滑地「最暗 → 最亮 → 最暗」往返：

```
phase = (now % period) / period
wave  = 0.5 − 0.5 × cos(2π × phase)          # 0 → 1 → 0
level = (1 − depth) + depth × wave            # 落在 (1-depth) ~ 1
```

用 `cos` 而不是 `sin`，是为了从"最暗"起步 → 慢慢亮起来，起始手感更自然。
默认 `period = 4.0s`（0.25Hz，和原来的 `breathe` 灯效一致）、`depth = 0.40`
（亮度在 `0.60 ~ 1.00` 之间起伏）。

呼吸是连续函数，本身已经平滑，所以输出**不做额外插值**——只有换歌时颜色突变才用
0.35s 时间常数（`SMOOTH_TAU`）柔化过渡，避免颜色"啪"地换掉。

### 封面取色方式

`--cover-layout` 二选一：

| 方式 | 表现 |
|---|---|
| `spatial`（默认） | 把封面按水平方向切成 8 条，每列取主色，**灯珠 i 对应封面第 i 列**——灯带从左到右就是封面从左到右。左红右蓝的封面，灯带就是左 4 颗红、右 4 颗蓝 |
| `weight` | 用九宫格算出带权重的多色，按权重铺到 8 颗灯上（权重大的颜色占多颗），呈现的是这张封面的**配色比例**而不是空间位置 |

两种方式都保留明度维度：暗的那几颗灯真的更暗。

## 串口协议

固件和电脑端靠这个通信，改固件时需要同步改 `led_host.py` 里的常量。

**帧格式**：`A5 5A | CMD | LEN | PAYLOAD[LEN] | CRC8`

CRC8 覆盖 CMD+LEN+PAYLOAD，多项式 0x07，初值 0x00。波特率 115200。

| CMD | 名称 | Payload | 用途 |
|---|---|---|---|
| `0x01` | SET_ALL | 24B，RGB×8 | 一次设定全部灯珠（主力命令，50Hz） |
| `0x03` | BRIGHTNESS | 1B | 全局亮度 |
| `0x04` | HEARTBEAT | 0B | 保活 |
| `0x06` | OFF | 0B | 立即熄灭（灯带 + 板载 LED，并标记「主机主动退出」） |
| `0x07` | STATUS_LED | 1B | 板载 LED 常驻灯态：`0`=灭 `1`=常亮 `2`=慢闪。带缓存，只在变化时发 |
| `0x08` | STATUS_PULSE | 1B | 板载 LED 短闪 N 下后自动熄灭（切歌 `2` / 状态切换 `3`）。**永不缓存** |
| `0x10` | HANDSHAKE | 0B | 回应固件版本号，电脑端启动时用它确认对面是本项目的固件 |

固件侧三条保护：

- **半帧 100ms 超时重置** — 一串干扰字节不会把解析状态机卡死
- **CRC 校验** — 坏帧直接丢弃
- **心跳 3 秒超时渐灭** — 电脑关机/休眠/进程退出时不会僵在最后一帧

渲染帧率是 **50Hz**（为电平表提的）：串口每帧 29 字节 × 50 = 1450 B/s，只占 115200 的 **12.6%**；
ESP8266 刷 8 颗 WS2812 只要 0.24ms，20ms 间隔绰绰有余，固件 3 秒心跳超时也不受影响。

## 常见问题

**设备管理器里驱动版本变回 3.9，灯不工作了**
Windows 更新会把 CH340 驱动顶到 3.9（有 bug）。跑上一级目录的 `ch340-fix.bat`（管理员），它会删掉驱动存储里的 3.9 包并禁止 WU 再推送。详见 `状态指示灯-方案设计.md`。

**pip 装包报 `from versions: none`**
换阿里源，见上面"装依赖"。

**灯一直不亮**
先 `--diagnose` 看有没有媒体会话。媒体源需要 WinRT 绑定 + Pillow，缺了程序会明确提示装什么；
装不齐时程序照常运行，只是灯保持熄灭。**麦克风没在使用时灯带本来就是全灭的**，
只有板载 LED 在 1Hz 闪，别误以为灯坏了。

**麦克风灯不跳档 / 一直全灭**
跑 `python led_host.py --diagnose` 看「麦克风体检」：会打印当前判定、正在使用的应用、
最近 8 条访问记录、**设备峰值**、固定量程与声音门限，以及 8 档「颗数 / 亮度」预览。
- 「占用检测不可用」= 注册表读不到（非 Windows，或系统隐私设置把麦克风访问整个关掉了）。
- 「电平接口不可用」= COM 峰值表拿不到，会降级成二值指示：在用就按 95% 亮度亮满 8 颗。
- 「在用」但灯全灭 = 去抖没走完（约 0.25 秒），或者真的没声音（低于声音门限）；
  这是特意做的：没声音时一颗都不亮。开着系统录音机说话测最直观。

**普通音量就 8 颗全亮 / 反过来怎么喊都上不去**
老版本「滚动峰值参考」的 bug，已改成固定量程。现在按麦克风增益校准一次即可：
用普通音量说话时跑 `--diagnose`，看「当前设备峰值」；总是满档就把
`--mic-full-peak` 调大（默认 0.35，例如 0.6），几乎不亮就调小（例如 0.15）。
前台可以直接 `python led_host.py --mic-full-peak 0.6` 试；
要让开机自启也用这个值，重跑一次 `--autostart install` 固化参数。

**灯一直是 8 颗不回落**
多半是某个应用崩溃/被强杀，没来得及写 `LastUsedTimeStop`，留下了 `Start > Stop`
的僵尸记录。脚本会忽略超过 6 小时的 `Start`，所以最多 6 小时后自动恢复；
想立刻清掉可以删 `ConsentStore\microphone` 下对应应用的 `LastUsedTimeStart`。

**板载 LED 一直在温柔呼吸**
那是「主机失联」提示，不是故障：后台服务没在跑（忘了装自启 / 被 `--autostart stop` 停了）、
USB 线断了、或者串口号不对。看 `host/logs/led_host.log` 能一眼分出是哪种。
主机正常推流后呼吸立刻停；Ctrl+C 退出会先发 `OFF`，所以手动关掉是安静的，不会呼吸。

**板载 LED 一直在 1Hz 闪 / 一直常亮是什么意思**
1Hz 闪 = 麦克风没被占用（待机，灯带全灭）；常亮 = 有程序在用麦克风。这是常驻状态，
不是故障。另外闪 2 下 = 切歌了，闪 3 下 = 灯效状态切换（放歌 ↔ 麦克风态 ↔ 熄灭），
那是事件脉冲，闪完会回到常驻状态。整块关掉用 `--no-status-led`。

**打不开串口**
Arduino IDE 的串口监视器、PlatformIO Monitor 会独占 COM 口，烧录或运行时必须关掉。也可能串口号不对，用 `--list-ports` 确认。

**睡一觉起来灯不亮了 / 串口断了**
已内置**自动重连**：断链后按 1→2→4→8…（上限 30 秒）指数退避重试，端口号变了也能按 CH340 描述重新找到；连上后自动重新握手并恢复亮度。日志会打印 `[!] 串口断开` 以及每次重试结果。若一直连不上（比如 USB 被拔掉），Ctrl+C 退出即可。

**媒体源显示"没有任何会话"**
确认播放器已注册到系统媒体接口：`python led_host.py --diagnose`。网易云的 AppUserModelID 是 `cloudmusic.exe`。

## 数据源实现说明

两个源。**媒体**（SMTC，系统媒体传输控制）优先：拿缩略图 → 九宫格配色 → 铺到灯带。
遍历**所有**会话而不只看 `get_current_session()`（网易云常不是系统认定的当前会话）。只在换歌时解码封面。

**封面配色算法**：切成 3×3 九宫格（中心块权重 1.8、边 1.1、四角 0.8，因为主体通常在中间）→ 每格各自量化取色 → 按 **HSV 分桶**合并同色系（色相 30° 一档）→ 取前 4 色归一化权重。

打分是三个维度：`像素占比 × 位置权重 × (0.65 + 0.35×饱和度) × (0.40 + 0.60×明度)`。

- **饱和度只做轻微加权**（0.65~1.0）。早期用 `(0.35 + 0.65×s)` 惩罚太重，白色(s=0)的权重只剩彩色的 35%，大块白底反而被小面积彩色抢走。
- **明度**让暗部权重降低但不清零，所以黑色多的封面会有几颗暗灯。

最终颜色的处理有两条铁律：

1. **绝不给饱和度设下限。** 一旦设了（试过 `sat_min=0.40`），白色(s=0)和黑白灰会被硬染成彩色——而灰度的色相恰好是 0（红），表现为"大块白色变成红橙"。现在 `sat_min=0`，黑白封面就是纯灰阶，靠明度出层次。
2. **明度用 gamma 提亮，不用 min-max 归一化。** 后者会把"最暗的那色"强行拉到下限，于是白底(v=1.0)上的一块亮红(v=0.90)会被当成"最暗"压成暗红(实测变成 RGB(76,17,12))。改成 `v^0.70` 后只抬暗部、几乎不动亮部，亮红保持 RGB(237,52,36)。整体偏暗的封面（最亮色仍 <0.75）再统一增益，避免灯几乎不亮。

四个踩过的坑：
- 合并必须用 HSV 不能用 RGB：按 RGB 量化会把同色系的深浅变化当成不同颜色，配出来几色几乎没差别
- 提亮只能设下限不能设统一值：`val_min=0.75` 会把所有颜色压成同一亮度，层次全丢
- 排除阈值不能太高：`v < 0.05` 会把「大片黑 + 小块亮」里的黑整个丢掉，现在改成 0.02
- 上面两条铁律：饱和度下限 = 白变红橙；min-max 归一化 = 亮色被压暗

**切歌响应**：注册 SMTC 的 `media_properties_changed` / `playback_info_changed` 事件，切歌时回调立刻触发采样；另有 0.5 秒轮询兜底（事件万一不派发也不会卡住）。媒体线程跑的是**常驻 asyncio 事件循环**而不是反复 `asyncio.run()`——否则事件回调根本没有机会被派发。

**切歌后颜色不更新的坑（已修）**：SMTC 的标题和封面**不是同时更新**的。原来用"标题变了才解码"做缓存，结果切歌瞬间读到的还是上一首的封面，标题却已经是新的 —— 颜色就永远锁死在旧封面上。现在改成比对**封面字节的 MD5**：切歌后置 pending，最多 5 秒内反复取封面，直到哈希真的变化才更新取色。

三个已知坑（代码里已处理）：

- `read_async()` 必须 await，否则第二次调用拿到空 buffer
- 新版 PyWinRT 里 `DataReader.read_bytes(n)` 会报 `TypeError`，正确写法是直接 `bytes(buffer)`
- 提亮只能设下限不能设统一值：`val_min=0.75` 会把所有颜色压成同一个亮度，配色层次全丢，现在用 0.60 且只补下限

## 网易云能拿到哪些 SMTC 信息

实测结果（2026-10，网易云 PC 客户端 `cloudmusic.exe`）：

**能拿到**

| 字段 | 值 |
|---|---|
| `source_app_user_model_id` | `cloudmusic.exe`（用来做 `--app-filter`） |
| `title` | 歌名 ✓ |
| `artist` | 艺术家 ✓ |
| `thumbnail` | 封面图 ✓（本项目就靠它） |
| `playback_status` | 播放状态：Playing / Paused / Stopped 等 ✓ |
| Controls | `is_pause_enabled`、`is_next_enabled`、`is_previous_enabled` 均为 True |

**拿不到**（返回空、0 或 None）

| 字段 | 实际返回 |
|---|---|
| `album_title` / `album_artist` / `subtitle` | 空字符串 |
| `genres` / `track_number` / `album_track_count` | 空 / 0 |
| `playback_rate` / `is_shuffle_active` / `auto_repeat_mode` | None |
| 时间轴 `position` / `end_time` / `start_time` | 全是 0 —— **没有时长和进度** |
| `try_seek_async` | 方法不存在，无法拖动进度 |

**可以反向控制**（方法都存在，Controls 也标记为允许）：`try_pause_async`、`try_skip_next_async`、`try_skip_previous_async`、`try_toggle_play_pause_async`。也就是说理论上能让灯去切歌，不过目前没这个需求。
